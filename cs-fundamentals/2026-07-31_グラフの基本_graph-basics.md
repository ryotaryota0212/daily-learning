# グラフの基本（表現方法・BFS・DFS）

## 概要
グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。SNSの友人関係、経路探索、依存関係解析など、現実の多くの問題をモデル化できる。BFS・DFSはグラフ探索の根幹であり、最短経路・連結性・トポロジカルソートなど広く応用される。データ構造の選択（隣接リスト vs 行列）が性能に直結するため、使い分けの判断基準を理解することが重要。

## 仕組みの要点

### グラフの種類
- **有向グラフ**：エッジに方向あり（A→B）。依存関係、URLリンク
- **無向グラフ**：エッジに方向なし（A—B）。友人関係、道路網
- **重み付きグラフ**：エッジにコストあり。距離や所要時間を表現

### 表現方法
**隣接リスト**（スパースグラフ向き）
- 各ノードが隣接ノードのリストを保持
- 空間: O(V+E)。実際のグラフの多くはスパースなためこちらが主流

**隣接行列**（密グラフ向き）
- V×Vの行列、matrix[i][j]=1でエッジあり
- 空間: O(V²)。エッジ確認がO(1)だが、V=10万なら10^10要素で非現実的

### BFS（幅優先探索）
- **キュー**を使い、起点から近い順に探索
- 重みなしグラフで**最短経路**を保証
- 手順：起点をキューに入れ→取り出して未訪問の隣接ノードをキューに追加→繰り返す

### DFS（深さ優先探索）
- **スタック（または再帰）**を使い、一方向に深く進む
- **連結成分検出・トポロジカルソート・サイクル検出**に使う
- 手順：深く進む→行き止まりでバックトラック→未探索の枝を探索

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS / DFS | O(V+E) | O(V²) |
| エッジ確認 | O(degree) | O(1) |
| 空間 | O(V+E) | O(V²) |

## コード例（Python）

```python
from collections import deque

graph = {0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2]}

def bfs(start):
    visited, queue = {start}, deque([start])
    while queue:
        node = queue.popleft()
        print(node)
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                queue.append(nb)

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node)
    for nb in graph[node]:
        if nb not in visited:
            dfs(nb, visited)
```

## よくある誤解・落とし穴
- **BFSは重みなしグラフのみ最短経路保証**。重みありは Dijkstra / Bellman-Ford が必要
- **DFSの再帰は深いグラフでスタックオーバーフローの危険**（Python のデフォルト再帰上限は1000）→反復DFSで回避
- **訪問済みチェックを忘れると無限ループ**（有向サイクルがある場合に特に注意）
- **隣接行列を疎なグラフに使うとメモリ爆発**。SNSグラフ（V=数億）では到底使えない

## 実務での使いどころ

- **FastAPI**: ルーター間の依存関係を有向グラフでモデル化し、循環依存をDFSで検出できる
- **Neon（PostgreSQL）**: テーブル間の外部キー関係はグラフ構造。クエリプランナーはJOINの順序を内部的にグラフ探索で決定している
- **Cloud Run**: マイクロサービスの呼び出しグラフを可視化し、障害伝播の影響範囲をBFSで特定。デプロイ順序はトポロジカルソート（DFSベース）で決定
- **依存パッケージ解決**: `pip` や `npm` が依存グラフのサイクル検出と解決順序決定にDFSを使用
