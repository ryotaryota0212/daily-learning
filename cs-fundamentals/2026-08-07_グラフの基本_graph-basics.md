# グラフの基本（表現方法・BFS・DFS）

## 概要

グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。SNSの友人関係、ルーティング、依存関係解決など、現実の問題の多くはグラフとして表現できる。BFS・DFSは全探索の基礎であり、最短経路・トポロジカルソート・サイクル検出など応用が広い。

---

## 仕組みの要点

### グラフの種類
- **有向グラフ（Directed）**: エッジに向きあり（A→B ≠ B→A）
- **無向グラフ（Undirected）**: 向きなし（A–B = B–A）
- **重み付きグラフ**: エッジにコスト（距離・時間など）を持つ
- **DAG（有向非巡回グラフ）**: サイクルなしの有向グラフ。タスク依存関係などに使う

### 表現方法

**隣接リスト（Adjacency List）**
- 各ノードに接続先リストを持たせる
- メモリ: O(V + E)（疎グラフに有利）
- エッジ存在確認: O(degree)

**隣接行列（Adjacency Matrix）**
- V×Vの2次元配列。`matrix[i][j] = 1` でエッジ存在
- メモリ: O(V²)（密グラフに有利）
- エッジ存在確認: O(1)

```
隣接リスト例（無向グラフ）:
0: [1, 2]
1: [0, 3]
2: [0, 3]
3: [1, 2]
```

### BFS（幅優先探索）
- キューを使い、起点から近い順に探索
- **最短ホップ数**の経路を保証（重みなしグラフ）
- 処理の流れ:
  1. 起点をキューに追加、訪問済みマーク
  2. キューからノードを取り出し、未訪問の隣接ノードをキューに追加
  3. キューが空になるまで繰り返す

### DFS（深さ優先探索）
- スタック（または再帰）を使い、できる限り深く進んでから戻る
- **サイクル検出・トポロジカルソート・連結成分**の探索に適する
- 処理の流れ:
  1. 起点から再帰的に隣接ノードへ
  2. 訪問済みフラグで無限ループ防止
  3. バックトラック時に後処理可能（後順DFS）

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS / DFS | O(V + E) | O(V²) |
| エッジ追加 | O(1) | O(1) |
| エッジ確認 | O(degree) | O(1) |
| メモリ | O(V + E) | O(V²) |

- V = 頂点数、E = 辺数
- 疎グラフ（E << V²）: 隣接リストが有利
- 密グラフ（E ≈ V²）: 隣接行列でも許容範囲

## コード例（Python）

```python
from collections import deque

# 隣接リストで無向グラフを構築
graph = {0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2]}

def bfs(start):
    visited, queue = {start}, deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    result = [node]
    for neighbor in graph[node]:
        if neighbor not in visited:
            result += dfs(neighbor, visited)
    return result

print(bfs(0))  # [0, 1, 2, 3]
print(dfs(0))  # [0, 1, 3, 2]
```

---

## よくある誤解・落とし穴

- **BFSは最短経路を保証するが、重み付きグラフでは不可** → 重みありはDijkstra法を使う
- **DFSの再帰は深さが大きいとスタックオーバーフロー** → Pythonのデフォルトは1000。`sys.setrecursionlimit()` または反復DFSに書き換える
- **訪問済みフラグを忘れると無限ループ** → 特に無向グラフで親ノードへ戻り続ける
- **隣接行列は疎グラフに使うとメモリ無駄** → V=10万なら100億要素になる
- **有向グラフのBFSで到達不能なノードがある** → 全ノード探索が必要な場合は全頂点を起点にループ

## 実務での使いどころ

**個人開発（FastAPI + Neon + Cloud Run）との関連:**

- **依存関係の解決**: タスクやマイグレーションの順序をDAG + トポロジカルソートで決定。Alembicのマイグレーション管理が内部で行っているのと同じ原理
- **API間の依存グラフ**: マイクロサービス化した際のサービス間の依存関係を可視化・循環参照検出
- **レコメンデーション**: Neonに格納したユーザーの行動履歴をグラフとしてモデル化し、関連コンテンツをBFSで探索
- **ルーティング最適化**: Cloud Run上で複数のワーカーが連携する場合、タスクのDAGをBFSで処理順に並べる
- **フロントエンドの依存解析**: バンドラー（Webpack, Vite）はimportグラフをDFSで解析して循環依存を検出している
