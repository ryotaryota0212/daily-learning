# グラフの基本（表現方法、BFS、DFS）

## 概要

グラフは「頂点（ノード）」と「辺（エッジ）」からなるデータ構造で、SNSの友人関係・ルート検索・依存関係解決など現実問題の多くをモデル化できる。BFS/DFSの2大探索アルゴリズムを理解すれば、最短経路・閉路検出・トポロジカルソートなど幅広い問題に応用できる。FastAPIのルーティング依存関係やCloud Runサービス間の呼び出し順序もグラフとして捉えると設計が明確になる。

---

## 仕組みの要点

### グラフの種類

- **有向グラフ（Directed）**: 辺に向きあり。依存関係・フォロー関係
- **無向グラフ（Undirected）**: 辺に向きなし。友人関係・道路網
- **重み付きグラフ**: 辺にコスト（距離・時間）あり。経路コスト計算に使用
- **DAG（Directed Acyclic Graph）**: 閉路なし有向グラフ。タスクスケジューリング・Makefile

### グラフの表現方法

| 方法 | 空間計算量 | 辺の存在確認 | 隣接頂点列挙 | 向いている場面 |
|------|-----------|------------|------------|--------------|
| 隣接行列 | O(V²) | O(1) | O(V) | 密グラフ（辺が多い） |
| 隣接リスト | O(V+E) | O(degree) | O(degree) | 疎グラフ（辺が少ない） |

**実用上は隣接リストが主流**（Webのグラフは疎なことが多い）

### BFS（幅優先探索）

- キュー（FIFO）を使って「近い頂点から」順に探索
- 最短経路（辺の重みが均一な場合）を保証
- 処理フロー: 始点をキューに入れ → 取り出して隣接頂点をキューへ → 繰り返す

### DFS（深さ優先探索）

- スタック（または再帰）を使って「深く」優先で探索
- 閉路検出・トポロジカルソート・連結成分の検出に向く
- 処理フロー: 始点をスタックに積む → 取り出して隣接頂点をスタックへ → 繰り返す

---

## 計算量・パフォーマンス特性

| アルゴリズム | 時間計算量 | 空間計算量 | 備考 |
|------------|-----------|-----------|------|
| BFS | O(V+E) | O(V) | キューの最大サイズは最大幅 |
| DFS | O(V+E) | O(V) | 再帰の場合スタック深さがV |

- V = 頂点数、E = 辺数
- 密グラフ（E ≈ V²）では O(V²) に近づく

## コード例（Python）

```python
from collections import deque

graph = {
    0: [1, 2],
    1: [0, 3],
    2: [0, 3],
    3: [1, 2, 4],
    4: [3],
}

def bfs(start):
    visited = set([start])
    queue = deque([start])
    while queue:
        node = queue.popleft()
        print(node, end=" ")
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node, end=" ")
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(neighbor, visited)
```

---

## よくある誤解・落とし穴

- **visited管理の忘れ**: 閉路のあるグラフでvisitedを使わないと無限ループになる
- **BFSが常に最短経路とは限らない**: 辺に重みがある場合は Dijkstra が必要
- **DFSの再帰深さ**: Pythonのデフォルト再帰制限は1000。大規模グラフでは`sys.setrecursionlimit`かスタックを明示的に使う反復DFSにする
- **隣接行列のメモリ**: 100万頂点なら 10^12 バイト → 使えない。疎グラフには隣接リストを使う
- **有向グラフの連結性**: 有向の「強連結」と無向の「連結」は別概念。間違えると不具合の原因になる

## 実務での使いどころ

### FastAPI + Neon + Cloud Run スタックとの関連

- **依存解決**: FastAPIの `Depends()` チェーンはDAG。循環依存があると起動時にエラーになる。依存関係をグラフとして可視化するとデバッグしやすい
- **マイグレーション順序**: Neonのスキーママイグレーションで、テーブル間の外部キー依存をトポロジカルソート（DFS応用）で解決する
- **サービスメッシュ**: Cloud Runの複数サービス間の呼び出し関係はグラフ。閉路があるとデッドロックの原因になる
- **SQLのクエリプラン**: JOINのグラフ走査順序がクエリオプティマイザの核心。実行計画を読む際にグラフ的思考が役立つ
- **キャッシュ無効化**: Neonのデータ更新時にどのキャッシュを無効化すべきか、依存関係グラフをBFSで辿ると漏れなく特定できる
