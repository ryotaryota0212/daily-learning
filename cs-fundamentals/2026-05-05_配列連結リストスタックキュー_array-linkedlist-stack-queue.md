# 配列・連結リスト・スタック・キューの計算量と使い分け

## 概要

線形データ構造の4種は最も基本的なビルディングブロック。  
「どこにデータを入れ、どう取り出すか」によってパフォーマンスが大きく変わる。  
FastAPIのリクエストキューやDBのコネクション管理など、実務の至る所で使われている。  
計算量と特性を理解することで、適切なコレクション選択ができる。

---

## 仕組みの要点

### 配列（Array）
- メモリ上に**連続した領域**を確保。インデックスで O(1) アクセス
- 末尾追加は O(1) 償却（動的配列はリサイズ時に O(n) コピーが発生）
- 先頭・中間への挿入・削除は後続要素のシフトが必要で O(n)
- Python の `list` は動的配列。インデックスアクセスが多い場合に最適

### 連結リスト（Linked List）
- 各ノードが「データ + 次ノードへのポインタ」を持つ
- 先頭への挿入・削除は O(1)。インデックスアクセスは O(n)
- メモリが非連続なのでキャッシュ効率が悪い（実務ではほぼ配列で代替される）
- 双方向連結リストは前後どちらからも O(1) で追加・削除可能

### スタック（Stack）
- **LIFO（Last In First Out）**: push/pop が末尾に対して行われる
- 配列の末尾操作のみなので push/pop ともに O(1)
- 用途: 関数呼び出しのコールスタック、アンドゥ機能、DFS の実装

### キュー（Queue）
- **FIFO（First In First Out）**: enqueue が末尾、dequeue が先頭
- 配列で実装すると先頭削除が O(n)。**双方向キュー（deque）** を使えば O(1)
- 用途: タスクキュー、BFS の実装、バッファリング

---

## 計算量まとめ

| 操作 | 配列 | 連結リスト | スタック | キュー(deque) |
|------|------|-----------|---------|--------------|
| 先頭アクセス | O(1) | O(1) | O(1) | O(1) |
| 末尾アクセス | O(1) | O(n)※ | O(1) | O(1) |
| 中間アクセス | O(1) | O(n) | O(n) | O(n) |
| 先頭挿入 | O(n) | O(1) | — | O(1) |
| 末尾挿入 | O(1)償却 | O(n)※ | O(1) | O(1) |
| 中間挿入 | O(n) | O(n) | — | — |

※双方向連結リストかつ末尾ポインタあり の場合は O(1)

## コード例

```python
from collections import deque

# スタック: リストの末尾操作のみ使う
stack = []
stack.append(1)   # push O(1)
stack.append(2)
top = stack.pop() # pop  O(1) -> 2

# キュー: deque を使う（list の pop(0) は O(n) なので NG）
queue = deque()
queue.append("task1")    # enqueue O(1)
queue.append("task2")
first = queue.popleft()  # dequeue O(1) -> "task1"

# 連結リストが有利なケース: 先頭への頻繁な挿入
queue.appendleft("urgent")  # deque は両端 O(1)
```

---

## よくある誤解・落とし穴

- **`list.pop(0)` は O(n)**。キューに `list` を使うと大量データで顕著に遅くなる。`collections.deque` を使う
- **動的配列の償却 O(1)**は平均の話。リサイズが起きる瞬間は O(n)。リアルタイム性が必要な場合は注意
- **連結リストはキャッシュミスが多い**。理論上 O(1) でも実測では配列より遅いことが多い
- **Pythonの `list` はスタックとして使える**が、スレッドセーフではない。並行処理には `queue.Queue` を使う

## 実務での使いどころ

**FastAPI + Neon + Cloud Run スタック との関連:**

- **リクエスト処理キュー**: FastAPI の非同期タスク（`BackgroundTasks`）は内部的にキューで管理される。大量リクエスト時に deque の特性が効く
- **コネクションプーリング (Neon)**: DBコネクションはプールとしてスタックまたはキューで管理。LIFOスタック型はウォームコネクションを再利用しやすい
- **APIレスポンスのページネーション**: カーソルベースページネーションはリンクトリスト的な概念（次のカーソルへのポインタ）
- **DFS/BFS でのパス探索**: Cloud Run の依存サービスグラフをトポロジカルソートする際にスタック（DFS）を使う
