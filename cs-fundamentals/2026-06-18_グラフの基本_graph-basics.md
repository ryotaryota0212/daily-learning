# グラフの基本（表現方法、BFS、DFS）

## 概要

グラフは「ノード（頂点）」と「エッジ（辺）」で構成されるデータ構造。
SNSの友人関係、道路ネットワーク、タスクの依存関係など、現実世界の関係性をモデル化するのに最適。
BFS・DFSは最短経路・到達可能性・トポロジカルソートなど多くのアルゴリズムの基盤となる。

---

## 仕組みの要点

### グラフの種類
- **有向グラフ（Directed）**: A→B（一方向）。依存関係・ワークフロー
- **無向グラフ（Undirected）**: A—B（双方向）。友人関係・道路
- **重み付きグラフ**: エッジに数値（コスト・距離）を持つ
- **DAG（有向非巡回グラフ）**: 閉路なし。タスク依存解決に頻出

### グラフの表現方法

| 方式 | 構造 | 空間 | 隣接確認 | 向き |
|------|------|------|---------|------|
| 隣接リスト | `{A: [B, C]}` | O(V+E) | O(degree) | 疎グラフ向き |
| 隣接行列 | 2次元配列 | O(V²) | O(1) | 密グラフ向き |

疎グラフ（エッジ少）には隣接リスト、密グラフ（エッジ多）には隣接行列が効率的。

### BFS（幅優先探索）
- キューを使い、**近い順**にノードを探索
- 最短経路（重みなし）の保証あり
- 用途：最短ルート探索、レベル別処理

```
start → 隣接ノードをキューに追加 → キューから取り出して繰り返す
```

### DFS（深さ優先探索）
- スタック（または再帰）を使い、**深く**辿ってから戻る
- メモリ効率がよい（幅広いグラフでBFSはキューが巨大化）
- 用途：閉路検出、トポロジカルソート、連結成分

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS/DFS | O(V+E) | O(V²) |
| エッジ追加 | O(1) | O(1) |
| 隣接確認 | O(degree) | O(1) |
| 空間 | O(V+E) | O(V²) |

## コード例

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": [],
    "E": [],
}

def bfs(start):
    visited, queue = set([start]), deque([start])
    while queue:
        node = queue.popleft()
        print(node, end=" ")
        for n in graph[node]:
            if n not in visited:
                visited.add(n)
                queue.append(n)

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node, end=" ")
    for n in graph[node]:
        if n not in visited:
            dfs(n, visited)

bfs("A")  # A B C D E
dfs("A")  # A B D C E
```

## よくある誤解・落とし穴

- **BFSが常に最短経路**: 重みなしグラフのみ正確。重み付きはDijkstraが必要
- **DFSは再帰が限界**: Pythonはデフォルトで再帰深度1000。大グラフは明示的スタックを使う
- **訪問済み管理を忘れる**: 無向グラフで無限ループ、有向グラフで指数爆発
- **隣接リスト ≠ Set**: リストのまま使うと隣接確認がO(degree)になる（必要なら`set`に変換）
- **有向グラフの到達可能性**: A→BはB→Aを意味しない。逆方向探索が必要な場合は逆グラフを構築

## 実務での使いどころ

**FastAPI + Neon + Cloud Runスタックとの関連**

- **タスク依存解決**: ビルドパイプラインや処理フローをDAGで表現。DFSでトポロジカルソート
- **API設計のルーティング解析**: エンドポイント間の依存をグラフで可視化し、循環依存を検出
- **Neonのクエリ最適化**: クエリオプティマイザ内部でも結合順序をグラフ問題として解く
- **マイクロサービス依存管理**: サービス間の呼び出し関係をDAGとして管理し、障害の影響範囲をBFSで特定
- **レコメンド機能**: ユーザー・アイテムの関係グラフをBFSで辿り、類似ユーザーを発見
