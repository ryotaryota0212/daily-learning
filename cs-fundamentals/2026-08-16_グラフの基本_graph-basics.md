# グラフの基本（表現方法、BFS、DFS）

## 概要

グラフはノード（頂点）とエッジ（辺）で関係性を表すデータ構造。SNSのフォロー関係・依存関係解決・最短経路探索など、実務で頻出する問題の多くはグラフ問題に帰着できる。BFS/DFSはグラフ探索の基本パターンであり、あらゆる探索アルゴリズムの土台になる。

---

## 仕組みの要点

### グラフの種類

- **有向 vs 無向**: エッジに方向があるか（フォロー関係 vs 友人関係）
- **重み付き vs 非重み付き**: エッジにコストがあるか（地図の距離など）
- **DAG**（Directed Acyclic Graph）: 閉路なし有向グラフ。タスク依存関係に多用

### 表現方法の比較

| 方法 | メモリ | 辺の存在確認 | 隣接ノード列挙 | 向いているケース |
|------|--------|------------|--------------|----------------|
| 隣接リスト | O(V+E) | O(degree) | O(degree) | 疎なグラフ（実務の大半） |
| 隣接行列 | O(V²) | O(1) | O(V) | 密なグラフ、頻繁な辺検索 |

> 実務では隣接リストが基本。V=10万ノードなら行列は10GBになる。

### BFS（幅優先探索）の動き

1. スタートノードをキューに入れる
2. キューから取り出し、未訪問の隣接ノードをすべてキューに追加
3. 繰り返す → **最短ホップ数**が保証される

### DFS（深さ優先探索）の動き

1. スタートノードからスタック（または再帰）で深く進む
2. 行き詰まったら戻る
3. 再帰で実装するとシンプル → **全経路探索・閉路検出・トポロジカルソート**に使う

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS/DFS | O(V+E) | O(V²) |
| 辺の追加 | O(1) | O(1) |
| 辺の存在確認 | O(degree) | O(1) |

## コード例（Python）

```python
from collections import defaultdict, deque

# 隣接リストで有向グラフを構築
graph = defaultdict(list)
edges = [(0,1),(0,2),(1,3),(2,3),(3,4)]
for u, v in edges:
    graph[u].append(v)

def bfs(start):
    visited, dist = {start}, {start: 0}
    q = deque([start])
    while q:
        node = q.popleft()
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                dist[nb] = dist[node] + 1
                q.append(nb)
    return dist

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    for nb in graph[node]:
        if nb not in visited:
            dfs(nb, visited)
    return visited

print(bfs(0))   # {0:0, 1:1, 2:1, 3:2, 4:3}
print(dfs(0))   # {0,1,2,3,4}
```

## よくある誤解・落とし穴

- **BFSは最短経路を保証しない場合がある**: 辺に重みがある場合はダイクストラ法が必要。BFSは重みなし（ホップ数最小）のみ
- **再帰DFSはスタックオーバーフローに注意**: Python のデフォルト再帰上限は1000。深いグラフではスタックを明示的に使うか `sys.setrecursionlimit` を設定
- **訪問済みチェックを忘れると無限ループ**: 閉路があるグラフで必須
- **DFSで「最短」を求めるのは誤り**: DFSは最初に見つけた経路を返すだけで最短保証なし

## 実務での使いどころ

### FastAPI + Neon + Cloud Run スタックとの関連

- **依存関係グラフ**: マイクロサービスや非同期タスクの依存解決にDAG+トポロジカルソートを使う。タスクキューの実行順を決める場面で直接役立つ
- **DBのクエリプランナー**: PostgreSQL の実行計画はグラフ（ノード=演算子、エッジ=データフロー）。`EXPLAIN` を読む際の直感につながる
- **レコメンデーション**: ユーザー×アイテムの二部グラフをBFSで探索して「友達が買ったもの」を取得するパターン
- **Cloud Run のサービス依存**: 複数サービスの起動順制御もDAGで整理できる
