# グラフの基本（表現方法、BFS、DFS）

## 概要
グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。SNSの友人関係・ルーティング・依存関係解決・レコメンドエンジンなど、現実の多くの問題をモデル化できる。BFS・DFSという2つの探索アルゴリズムを押さえておくと、最短経路・到達可能性・トポロジカル順序など幅広い問題に対応できる。

---

## 仕組みの要点

### グラフの種類
- **有向グラフ（Directed）**: エッジに向きあり。フォロー関係、依存関係
- **無向グラフ（Undirected）**: 向きなし。友人関係、ネットワーク経路
- **重み付きグラフ**: エッジにコスト（距離・時間）付き
- **DAG（有向非巡回グラフ）**: サイクルなし。タスク依存関係に多用

### 表現方法
| 方式 | 空間計算量 | 特徴 |
|------|-----------|------|
| 隣接リスト | O(V + E) | 疎グラフに向く。実装が一般的 |
| 隣接行列 | O(V²) | 密グラフ・エッジ存在確認O(1) |
| エッジリスト | O(E) | Kruskalなど特定アルゴリズム向け |

### BFS（幅優先探索）
- キューを使い、近い頂点から順に探索
- **最短経路（重みなし）** を求めるのに最適
- 探索順: 始点 → 距離1の全頂点 → 距離2の全頂点 → …

### DFS（深さ優先探索）
- スタック（または再帰）で深く潜ってから戻る
- 到達可能性・連結成分・トポロジカルソートに使う
- バックトラッキングと相性が良い

---

## 計算量

| アルゴリズム | 時間 | 空間 |
|------------|------|------|
| BFS | O(V + E) | O(V) |
| DFS | O(V + E) | O(V) ※再帰深さ |

V = 頂点数、E = 辺数

---

## コード例（Python）

```python
from collections import deque

graph = {
    0: [1, 2],
    1: [0, 3],
    2: [0, 4],
    3: [1],
    4: [2],
}

def bfs(start):
    visited = set([start])
    queue = deque([start])
    while queue:
        node = queue.popleft()
        print(node, end=" ")
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                queue.append(nb)

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node, end=" ")
    for nb in graph[node]:
        if nb not in visited:
            dfs(nb, visited)
```

---

## よくある誤解・落とし穴

- **visitedの管理忘れ**: サイクルがあるグラフでvisitedなしだと無限ループ
- **BFS = 最短経路は重みなし限定**: 重みありはDijkstraが必要
- **再帰DFSのスタックオーバーフロー**: 頂点数が多い（数万〜）場合は反復実装に切り替える
- **隣接行列の使いどころ**: V=10万のグラフに隣接行列はメモリ超過（10^10バイト）

## 実務での使いどころ（FastAPI + Neon + Cloud Runスタック）

- **依存関係の循環検出**: マイクロサービスや設定ファイルの依存をDAGで表現し、DFSでサイクル検出
- **レコメンド**: Neonにユーザー×アイテムのエッジを持たせ、BFSで近傍ユーザーを辿る協調フィルタリング
- **APIのルーティング最適化**: Cloud Run間の呼び出しグラフをBFS解析し、不要なホップを削減
- **タスクキューの順序保証**: DAGのトポロジカルソートで、依存するジョブを正しい順序で実行
