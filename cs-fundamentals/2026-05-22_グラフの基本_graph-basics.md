# グラフの基本（表現方法・BFS・DFS）

## 概要

グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。SNSのフォロー関係、依存関係の解決、経路探索など、実務で頻出する問題をモデル化できる。BFS/DFSの仕組みを理解することで、「幅優先か深さ優先か」を正しく選択できる力がつく。

---

## 仕組みの要点

### グラフの種類
- **有向グラフ**：エッジに方向がある（フォロー関係、依存関係）
- **無向グラフ**：方向なし（友人関係、ネットワーク接続）
- **重み付きグラフ**：エッジにコストがある（地図の距離）
- **DAG（有向非巡回グラフ）**：循環なし → タスクスケジューリング、CI/CDパイプライン

### 表現方法の比較

| 方式 | 構造 | メモリ | 隣接ノード取得 | エッジ存在確認 |
|------|------|--------|----------------|----------------|
| 隣接リスト | `{node: [neighbors]}` | O(V+E) | O(degree) | O(degree) |
| 隣接行列 | `V×V の2次元配列` | O(V²) | O(V) | O(1) |

- **疎グラフ**（エッジが少ない）→ 隣接リストが有利
- **密グラフ**（エッジが多い）→ 隣接行列が有利

### BFS（幅優先探索）
- キューを使い、近い順に探索
- **最短ホップ数**（重みなしグラフ）を求めるのに適している
- 訪問済みフラグで無限ループを防ぐ
- 全ノードを訪問：O(V+E)

### DFS（深さ優先探索）
- スタック（または再帰）を使い、深く潜ってから戻る
- サイクル検出、トポロジカルソート、連結成分の列挙に適している
- 再帰で書くと実装がシンプルだが、深いグラフでスタックオーバーフロー注意
- 全ノードを訪問：O(V+E)

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| ノード追加 | O(1) | O(V²) |
| エッジ追加 | O(1) | O(1) |
| 隣接ノード列挙 | O(degree) | O(V) |
| BFS/DFS | O(V+E) | O(V²) |

## コード例（Python）

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": [],
    "E": [],
}

def bfs(start):
    visited, queue = set([start]), deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    result = [node]
    for neighbor in graph[node]:
        if neighbor not in visited:
            result += dfs(neighbor, visited)
    return result

print(bfs("A"))   # ['A', 'B', 'C', 'D', 'E']
print(dfs("A"))   # ['A', 'B', 'D', 'C', 'E']
```

---

## よくある誤解・落とし穴

- **BFS = 必ず最短経路** → 重みなしグラフに限る。重み付きはDijkstra法が必要
- **再帰DFSのスタック上限** → Pythonのデフォルト再帰上限は約1000。大きなグラフでは明示的スタックを使う
- **visitedのチェックタイミング** → キューへの追加時にマークしないと同じノードを複数回追加する
- **無向グラフのDFS** → 親ノードへ戻らないよう `parent` を管理する必要がある
- **隣接行列のメモリ** → 10万ノードのグラフで10GB超のメモリが必要になる

## 実務での使いどころ

### FastAPI + Neon + Cloud Runスタックとの関連

- **依存関係の解析（DAG）**：FastAPIのルーターやDIコンテナが内部で依存グラフを構築。循環依存はDFSで検出できる
- **マイグレーション順序の決定**：Neonへのスキーマ変更を安全な順序で適用するにはDAGのトポロジカルソートが使える
- **Cloud Runのリビジョン間の関係管理**：デプロイパイプラインの依存関係をDAGで表現すると並列実行できるタスクが明確になる
- **APIの到達可能性チェック**：エンドポイント間の呼び出し関係をグラフで表し、未到達パスや循環参照をBFS/DFSで検出する
