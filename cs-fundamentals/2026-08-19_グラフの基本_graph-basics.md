# グラフの基本（表現方法、BFS、DFS）

## 概要

グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。SNSの友人関係、地図の経路探索、依存関係の解決など、現実世界の問題の多くをグラフとしてモデル化できる。BFS・DFSはグラフ探索の基本であり、最短経路・トポロジカルソート・連結成分の検出など無数のアルゴリズムの土台になる。FastAPIのルーティング依存解決やCloud Runのサービス依存グラフにも応用できる。

---

## 仕組みの要点

### グラフの種類

- **有向グラフ (Directed)**: エッジに向きがある（例: フォロー関係）
- **無向グラフ (Undirected)**: エッジに向きがない（例: 友人関係）
- **重み付きグラフ**: エッジにコスト/距離がある（例: 地図）
- **DAG (有向非巡回グラフ)**: 閉路がない有向グラフ（例: タスク依存）

### 表現方法の比較

| 方式 | メモリ | 隣接確認 | 全エッジ列挙 | 向いている場面 |
|------|--------|----------|-------------|----------------|
| 隣接行列 | O(V²) | O(1) | O(V²) | 密グラフ |
| 隣接リスト | O(V+E) | O(degree) | O(V+E) | 疎グラフ（実務の大多数）|

実務では**隣接リスト**（`dict[node] = list[neighbors]`）がほぼ標準。

### BFS（幅優先探索）の仕組み

1. 開始ノードをキューに積む
2. キューから取り出し、未訪問の隣接ノードを全てキューに追加
3. キューが空になるまで繰り返す

- **特性**: 最初に到達したときが最短ステップ数（重みなし）
- **用途**: 最短経路、連結成分確認、レベル順処理

### DFS（深さ優先探索）の仕組み

1. 開始ノードをスタック（または再帰）で処理
2. 隣接ノードを1つ選び、到達不能になるまで深く進む
3. バックトラックして次の枝を探索

- **特性**: メモリ効率がよい（スタック深さ = 木の高さ）
- **用途**: 閉路検出、トポロジカルソート、連結成分、バックトラッキング

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS/DFS | O(V+E) | O(V²) |
| 隣接ノード列挙 | O(degree) | O(V) |
| エッジ追加 | O(1) | O(1) |
| エッジ存在確認 | O(degree) | O(1) |

V = 頂点数、E = エッジ数。疎グラフ（E << V²）では隣接リストが圧倒的に有利。

## コード例（Python）

```python
from collections import deque

# 隣接リストで表現
graph = {
    'A': ['B', 'C'],
    'B': ['A', 'D'],
    'C': ['A', 'D'],
    'D': ['B', 'C'],
}

def bfs(start):
    visited = {start}
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

def dfs(start, visited=None):
    if visited is None:
        visited = set()
    visited.add(start)
    result = [start]
    for neighbor in graph[start]:
        if neighbor not in visited:
            result.extend(dfs(neighbor, visited))
    return result

print(bfs('A'))  # ['A', 'B', 'C', 'D']
print(dfs('A'))  # ['A', 'B', 'D', 'C']
```

---

## よくある誤解・落とし穴

- **訪問済み管理を忘れる**: 無限ループになる。`visited` セットは必須
- **DFSの再帰深度**: Pythonのデフォルト再帰制限は1000。大きなグラフではスタックを使った反復版に変換する
- **BFSで最短経路は重みなしグラフのみ**: 重み付きはダイクストラ法が必要
- **隣接行列のメモリ**: 100万ノードでは10^12バイト必要で現実的でない
- **有向グラフのBFS/DFSは向きを無視しない**: エッジの向きに従って探索する

## 実務での使いどころ

### FastAPI + Neon + Cloud Runスタックとの関連

- **依存注入グラフ**: FastAPIの `Depends()` チェーンは有向グラフ。循環依存があるとエラーになる（DAGを要求している）
- **DBの外部キー関係**: Neon(PostgreSQL)のテーブル間の参照関係をグラフとして把握すると、JOIN順やカスケード削除の影響範囲が見えやすくなる
- **Cloud Runのサービス依存**: マイクロサービス間の呼び出し関係をDAGとして整理することで、起動順序や障害影響の伝播を把握できる
- **APIエンドポイントのアクセス制御**: ロールと権限の継承関係を有向グラフで表現し、BFSで到達可能な権限を計算する手法がある
