# グラフの基本（表現方法・BFS・DFS）

## 概要

グラフはノード（頂点）とエッジ（辺）で構成されるデータ構造。ネットワーク経路探索・SNSの友人関係・依存関係解決（npm/pip）など、実世界の問題の多くがグラフとして表現できる。BFS/DFS を理解すると「到達可能かどうか」「最短距離」「循環の検出」を自力で実装できるようになる。

## 仕組みの要点

### グラフの種類

- **有向グラフ (Directed)**: エッジに向きあり（フォロー関係、依存関係）
- **無向グラフ (Undirected)**: エッジに向きなし（友人関係、道路網）
- **重み付きグラフ**: エッジにコスト付き（距離、レイテンシ）
- **DAG (有向非循環グラフ)**: 循環なし。タスクスケジューリングに多用

### グラフの表現方法

| 方法 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| 空間計算量 | O(V + E) | O(V²) |
| エッジ探索 | O(degree) | O(1) |
| 向き不向き | 疎グラフ向き | 密グラフ向き |

実務ではほぼ**隣接リスト**を使う（Webのグラフは疎になりやすい）。

### BFS（幅優先探索）

- キューを使う
- 始点から近い順に探索 → **最短ホップ数**を求めるのに使う
- 処理順: 始点 → 距離1の全ノード → 距離2の全ノード → ...

### DFS（深さ優先探索）

- スタック（または再帰）を使う
- 到達可能性の確認・サイクル検出・トポロジカルソートに使う
- 処理順: 一本道を奥まで掘ってから戻る

## 計算量・パフォーマンス特性

| 操作 | BFS / DFS |
|------|-----------|
| 時間計算量 | O(V + E) |
| 空間計算量 | O(V)（キュー/スタック/訪問済みセット） |

V = ノード数、E = エッジ数。両アルゴリズムとも全エッジを1回ずつ走査する。

## コード例（Python）

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D", "E"],
    "C": ["F"],
    "D": [], "E": [], "F": []
}

def bfs(start):
    visited, queue = set([start]), deque([start])
    while queue:
        node = queue.popleft()
        print(node, end=" ")
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)

def dfs(node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node, end=" ")
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(neighbor, visited)
```

## よくある誤解・落とし穴

- **訪問済みチェックを忘れる**: 無限ループになる。必ず `visited` セットを使う
- **BFS で最短経路と思いきや重み付きグラフ**: 重みがあれば Dijkstra が必要（BFS はホップ数最短）
- **再帰 DFS のスタックオーバーフロー**: 深さが数万になる場合はスタックを使った反復 DFS に切り替える
- **有向グラフと無向グラフの混同**: 隣接リストの構築時に双方向に追加するかどうかで挙動が変わる

## 実務での使いどころ

**FastAPI + Neon + Cloud Run スタックとの関連:**

- **API 依存関係の可視化**: マイクロサービス間の呼び出し関係をグラフで表現し、循環依存の検出に DFS を使う
- **Neon でのリレーション探索**: 再帰 CTE（`WITH RECURSIVE`）はグラフの BFS に相当。コメントスレッドや組織階層をたどる際に使う
- **Cloud Run のタスク順序**: デプロイパイプラインの依存解決はトポロジカルソート（DFS ベース）の典型例
- **レコメンド機能**: ユーザー-アイテムの二部グラフを BFS でたどることで「共通の興味を持つユーザー」を探索できる
