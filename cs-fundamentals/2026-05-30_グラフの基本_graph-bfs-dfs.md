# グラフの基本（表現方法・BFS・DFS）

## 概要

グラフは「ノード（頂点）」と「エッジ（辺）」で関係性を表すデータ構造。SNSのフォロー関係、経路探索、依存関係解決など、現実の問題の多くはグラフとして定式化できる。BFS・DFSはグラフ探索の基本で、最短経路・到達可能性・トポロジカル順序など多くのアルゴリズムの土台になる。

---

## 仕組みの要点

### グラフの種類

- **有向グラフ（Directed）**: エッジに方向あり（A→B ≠ B→A）。フォロー関係、依存関係など
- **無向グラフ（Undirected）**: エッジに方向なし（A-B = B-A）。友達関係、道路網など
- **重み付きグラフ（Weighted）**: エッジにコスト（距離、時間）がある
- **DAG（有向非巡回グラフ）**: サイクルなし。タスクの依存関係などで重要

### 表現方法の比較

| 方法 | 空間 | 隣接チェック | 隣接ノード列挙 | 向いている場面 |
|------|------|-------------|--------------|--------------|
| 隣接行列 | O(V²) | O(1) | O(V) | 密なグラフ、エッジ存在確認が多い |
| 隣接リスト | O(V+E) | O(degree) | O(degree) | 疎なグラフ（実務の多くはこれ） |

```
隣接リスト例（無向グラフ）:
0 -- 1 -- 2
|         |
3 ---------

graph = {
  0: [1, 3],
  1: [0, 2],
  2: [1, 3],
  3: [0, 2]
}
```

### BFS（幅優先探索）

- キューを使い、近い順に探索
- **最短経路（辺の重みが同一の場合）** を保証する
- 探索順: 起点 → 距離1のノード全て → 距離2のノード全て → ...

```
BFS イメージ（起点=0）:
探索順: 0 → 1,3 → 2（2は1からも3からも繋がるが一度だけ訪問）
```

### DFS（深さ優先探索）

- スタック（または再帰）を使い、深く潜る
- 経路の存在確認、閉路検出、トポロジカルソートに使う
- 探索順: 起点 → 一本道を端まで → バックトラックして別の枝へ

---

## 計算量・パフォーマンス特性

| 操作 | 隣接リスト | 隣接行列 |
|------|-----------|---------|
| BFS/DFS | O(V+E) | O(V²) |
| エッジ追加 | O(1) | O(1) |
| エッジ存在確認 | O(degree) | O(1) |

- V: 頂点数、E: 辺数
- 実務のグラフは疎（E << V²）が多いので隣接リストが有利

## コード例

```python
from collections import deque

graph = {0: [1, 3], 1: [0, 2], 2: [1, 3], 3: [0, 2]}

def bfs(graph, start):
    visited = set([start])
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

def dfs(graph, start, visited=None):
    if visited is None:
        visited = set()
    visited.add(start)
    result = [start]
    for neighbor in graph[start]:
        if neighbor not in visited:
            result += dfs(graph, neighbor, visited)
    return result

print(bfs(graph, 0))  # [0, 1, 3, 2]
print(dfs(graph, 0))  # [0, 1, 2, 3]
```

---

## よくある誤解・落とし穴

- **BFS = 最短経路？**: 辺の重みが均一な場合のみ。重み付きグラフはDijkstra法が必要
- **DFSは再帰でOK？**: グラフが深い場合、再帰の深さ制限（Pythonデフォルト1000）で失敗する。大きなグラフはスタックで反復実装を
- **visitedセットを忘れる**: 閉路があると無限ループ。必ず訪問済みを管理
- **木とグラフを混同**: 木はグラフの特殊ケース（連結・非巡回・無向）。グラフには閉路や非連結がある
- **隣接行列を使いすぎる**: V=10万ノードで行列は100億エントリ → メモリ不足

## 実務での使いどころ

**FastAPI + Neon + Cloud Run スタックとの関連:**

- **依存関係解決**: Cloud RunサービスのデプロイやNeonのマイグレーション順序をDAG+トポロジカルソートで管理できる
- **APIルートの到達可能性チェック**: サービス間の呼び出し関係をグラフとして表現し、循環依存を検出
- **DB のリレーション探索**: Neon上でユーザー→注文→商品のような関係を再帰CTEで辿る操作は、実質的にDFS相当
- **レコメンデーション**: ユーザーとアイテムの二部グラフをBFSで探索するシンプルな協調フィルタリング

**覚えておく判断基準:**
- 最短距離・最近傍 → BFS（重み均一）またはDijkstra（重みあり）
- 全経路探索・閉路検出・依存順序 → DFS
- ノード数・辺数が多い → 隣接リスト一択
