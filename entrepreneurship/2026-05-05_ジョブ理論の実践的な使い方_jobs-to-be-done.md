# ジョブ理論（Jobs to be Done）の実践的な使い方

## 概要

なぜユーザーはあなたのプロダクトを使うのか？「機能が欲しい」からではなく、「片付けたい仕事がある」から使う。ジョブ理論（JTBD）はその「仕事」を軸にプロダクトを設計するフレームワーク。競合はカテゴリが違っても「同じジョブを奪い合う」。個人開発者が陥りがちな「機能の羅列」ではなく「ジョブの解決策」として設計することで、PMFへの最短距離を歩める。

---

## 核となる考え方

- **「雇う」メタファー**: ユーザーはプロダクトを「ある仕事をするために雇う」。使わないときは「解雇」している
- **3つのジョブ次元**:
  - 機能的ジョブ（実際にやりたいこと）
  - 感情的ジョブ（どう感じたいか）
  - 社会的ジョブ（他者にどう見られたいか）
- **競合の再定義**: Excelのピボットテーブルとノーコードツールは同じジョブを取り合う。カテゴリで競合を見るな
- **状況がジョブを決める**: 「いつ・どんな状況で」が同じでも、ジョブは人によって異なる
- **進歩の力学**: ユーザーは「現状から望む状態への進歩」を求めている

---

## 実践フレームワーク・ステップ

### Step 1: ジョブステートメントを書く

```
[状況] のとき、私は [動機/目的] したい。
それによって [期待する結果] を得たい。
```

例: 「週次レポートを作る作業があるとき、データを素早くグラフ化したい。それによって上司への説明を自信を持って行いたい」

### Step 2: スイッチングインタビューで掘る

購入・乗り換えのタイミングに絞ってヒアリングする。

| 質問 | 目的 |
|------|------|
| それを使い始めた「最初の考え」はいつ生まれましたか？ | トリガーを特定 |
| 前に使っていたものを「もう限界」と感じた瞬間は？ | プッシュ力を特定 |
| 検討したけどやめた選択肢は？ | 引力と不安を特定 |
| 最初に試してみようと思ったきっかけは？ | プル力を特定 |

### Step 3: 4つの力でスイッチを分析する（JTBD Forces）

```
スイッチ = (Push + Pull) - (Inertia + Anxiety)

Push   = 現状への不満・限界感
Pull   = 新しい解決策への期待
Inertia= 変えたくない慣性・習慣
Anxiety= 新しいものへの不安・リスク
```

- **個人開発での活用**: ランディングページはPullを最大化し、Anxietyを下げる設計にする

### Step 4: ジョブからプロダクト仕様に変換する

1. メインジョブを1つ定義する（複数は危険）
2. 関連する小ジョブ（サブジョブ）を列挙する
3. 各ジョブに対して「今どう解決しているか」を競合として把握する
4. 自分のプロダクトがどのジョブで「最高の解決策」かを絞り込む

## 事例

### 成功例: Notion

- 表面上の競合: Evernote（メモ）、Confluence（Wiki）、Asana（タスク）
- 実際のジョブ: 「散らかった情報を1か所に整理して、チーム・個人の思考を見える化したい」
- 同じジョブに気づき、カテゴリを超えて「思考OS」として設計した

### 個人開発の例

あるソロファウンダーがフリーランス向け請求書ツールを作った。最初は「請求書を速く作れる」をPushした。しかし調査で本当のジョブは「クライアントへの支払い催促を感情的なストレスなく行いたい（社会的・感情的ジョブ）」だと判明。自動リマインダー機能を中心に再設計したところ、チャーンが激減した。

---

## アンチパターン

- **「ユーザーが欲しいと言った機能」を作る**: ユーザーは解決策を提案するが、本当のジョブは別にある（ドリルの穴の法則）
- **デモグラフィックでペルソナを切る**: 「30代男性会社員」はジョブを教えてくれない。「月曜朝に上司への報告資料を急いで準備する状況」の方が有用
- **複数ジョブを同時に解こうとする**: 1プロダクトで複数の異なるジョブを狙うと、全部中途半端になる
- **機能的ジョブだけ見る**: 感情・社会ジョブを無視すると、競合に差別化できない（スペックで負ける）

## 明日から試せるアクション

1. **既存ユーザー3人にスイッチングインタビューを実施する**  
   「このプロダクトを使い始めようと思った最初の瞬間を教えてください」から始める

2. **自分のプロダクトのジョブステートメントを1文で書く**  
   「〇〇のとき、△△したい。そうすることで□□したい。」に当てはめ、チームや仲間に見せて違和感がないか確認する

3. **競合をカテゴリでなくジョブで再リストアップする**  
   同じジョブを解決している手段（Excelでの手作業、他ツール、何もしない）を5つ書き出し、自分のプロダクトが勝てるシナリオを1つ特定する
