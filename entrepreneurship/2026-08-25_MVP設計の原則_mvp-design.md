# MVP設計の原則：何を作らないかを決める技術

## 概要

MVP（Minimum Viable Product）は「最小限の機能で最大の学びを得る製品」だ。よく誤解されるが、「機能を削ったプロダクト」ではなく「最速で仮説を検証できる実験装置」である。個人開発者にとってMVPは特に重要で、限られた時間と予算を「誰も使わないものを作ること」に費やさないための防衛手段になる。

## 核となる考え方

- **作ることより「作らないこと」を先に決める**：機能リストを並べてから削るのではなく、最初から「これがなくても検証できるか？」を問う
- **MVPの目的は販売ではなく学習**：ユーザーが「使う理由」を持つか、「払う意思」があるかを確認すること
- **Viableは「生存可能」**：ユーザーが実際に使える最低限の体験を保証する（バグだらけ・UXが壊滅的では学びにならない）
- **スコープを固定するより問いを固定する**：「このMVPで何を証明するのか」を1行で言えなければ、スコープが広すぎる
- **Fake it before you make it**：自動化する前に手動で、コードを書く前にスプレッドシートで、の順番を守る

## 実践フレームワーク・ステップ

### Step 1：検証したい仮説を1行で書く

```
「〇〇な人は、△△という課題を抱えていて、□□があれば金を払う」
```

例：「副業エンジニアは、確定申告の計算が面倒で、自動化ツールがあれば月1,000円払う」

### Step 2：MVP以前の検証（ゼロコスト確認）

| 手法 | コスト | 検証できること |
|------|--------|--------------|
| ランディングページ + メール登録 | ほぼ0 | 需要の有無 |
| SNS投稿でリアクション計測 | 0 | 刺さるメッセージ |
| Notionページで概念説明 | 0 | 理解できるか |
| 既存ツール組み合わせで手動提供 | 時間のみ | 支払い意思 |

→ **コードを書く前にこれらをやれるか確認する**

### Step 3：MVPスコープ決定チェックリスト

各機能に対して以下を問う：

- [ ] これがなくても「仮説」は検証できるか？ → あるならカット
- [ ] これがなければユーザーは使えないか？ → なければカット
- [ ] 手動でも同じ検証ができるか？ → できるならまず手動で

### Step 4：MVP完成の判断基準を先に決める

- 「何人が使ったら成功？」→ 例：10人の非知人ユーザーが1週間継続
- 「何の数値を見る？」→ 例：7日リテンション率、初回課金率
- 期間を決める → 例：4週間以内に結果が出なければピボット検討

## 成功・失敗の事例

### 成功例：Dropbox（有名だが本質的）
- MVPはコードではなく「動画」：機能を説明する3分の説明動画
- 登録者が一夜で7万5千人 → 需要を証明してから開発
- 個人開発応用：まず「使い方動画 + ウェイトリスト」ページを作る

### 成功例：個人開発者のSaaS立ち上げ典型パターン
- 自分自身の課題 → Twitterで「こんなツール作ってる」と投稿 → DM来た人に無料で使わせる → 改善してから課金

### 失敗例：機能を詰め込みすぎたMVP
- 「せっかくだから」で認証・ダッシュボード・通知・APIまで作った
- 3ヶ月かけてリリースしたが誰も使わなかった
- 原因：コアの価値（課題解決）が埋もれて伝わらなかった

## アンチパターン

- **「あと少しで完成」症候群**：もう一個機能を足せば使ってもらえると思い続けて永遠にリリースしない
- **知人にしか見せない**：「良いと思う」という社交辞令を需要と誤認する
- **技術的にクールなものを作りたい欲求**：検証に不要な技術スタックの選定（GraphQL、マイクロサービスなど）
- **MVPを「小さいプロダクト」と捉える**：機能数の問題ではなく「仮説を最速で検証できるか」の問題
- **ユーザーフィードバックを集める前にスケールを考える**：まだPMFしていないのに広告費をかける

## 明日から試せるアクション

1. **今作っている（または作ろうとしている）ものの仮説を1行で書く** → 「〇〇な人は△△という課題があり□□で金を払う」の形式で。書けなければスコープが不明確なサイン

2. **機能リストの各項目に「これがなくても仮説は検証できるか？」と問い、YESならカット** → 残ったものだけがMVPスコープ

3. **コードを書く前に「手動版MVP」を試す** → Notionページ・スプレッドシート・DM対応など。5人の他人に見せてリアクションを見る
