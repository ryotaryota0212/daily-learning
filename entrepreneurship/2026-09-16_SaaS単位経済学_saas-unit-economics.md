# SaaSの単位経済学：LTV・CAC・Churn Rate・MRR/ARRの実践

## 概要

SaaSビジネスを運営するうえで、「単位経済学（Unit Economics）」は事業の健全性を判断する最重要指標。
売上が伸びていても、1顧客あたりの収益がコストを下回っていれば赤字が拡大するだけ。
ソロファウンダーが限られたリソースを最適配分し、スケールに向けた投資判断をするためには、この数字を「自分の指標」として読み解く力が必要。

---

## 核となる考え方

### 基本指標の定義

- **MRR（Monthly Recurring Revenue）**: 毎月の定期収益。単発収益は除く
- **ARR（Annual Recurring Revenue）**: MRR × 12。投資家向けに使いやすい指標
- **CAC（Customer Acquisition Cost）**: 顧客1人を獲得するためのコスト
  - 計算式: `CAC = 総獲得コスト（広告費+営業コスト） ÷ 新規顧客数`
- **LTV（Lifetime Value）**: 顧客1人が生涯にわたってもたらす収益
  - 計算式: `LTV = ARPU（顧客1人あたり月次収益） ÷ Churn Rate（月次解約率）`
- **Churn Rate（解約率）**: 毎月失う顧客の割合
  - 計算式: `月次Churn = 当月解約数 ÷ 月初顧客数`

### ゴールデンルール

- **LTV / CAC ≥ 3** : 健全なSaaSビジネスの最低ライン
- **CAC回収期間 ≤ 12ヶ月** : それ以上かかると資金繰りが危険
- **月次Churn ≤ 2%** : 年間換算で約22%解約。これ以上だとバケツの底が抜ける

### 個人開発者が見落としがちな点

- 自分の作業時間もCACに含める（時給換算で計算すること）
- 無料ユーザーへのサポートコストもChurnに影響する
- Churn Rateが高いうちは広告費を増やしても焼け石に水

## 実践フレームワーク

### STEP 1: 現状の数字を把握する（30分）

```
月初顧客数: ___ 人
当月解約数: ___ 人
→ 月次Churn = 解約数 ÷ 月初顧客数 = ___%

月次収益合計（MRR）: ___ 円
有料顧客数: ___ 人
→ ARPU = MRR ÷ 顧客数 = ___ 円/人

→ LTV = ARPU ÷ Churn Rate = ___ 円
```

### STEP 2: CACを計算する

```
先月の広告費 + ツール費 + 自分の営業時間（時給×時間）= 総コスト
先月の新規有料顧客数: ___ 人
→ CAC = 総コスト ÷ 新規顧客数 = ___ 円
```

### STEP 3: LTV/CACで健全性チェック

| LTV/CAC | 判断 | アクション |
|---------|------|-----------|
| 1未満   | 危険 | 価格を上げるか、獲得コストを下げる |
| 1〜3    | 要改善 | Churn低減かARPU向上に注力 |
| 3以上   | 健全 | 成長投資を加速できる |

### STEP 4: Churn改善の優先順位

1. **解約直前のユーザー特定** → 最終ログインから7日以上経過したユーザーにアラート
2. **解約理由の収集** → 解約フォームに「理由を選択」を必須にする
3. **30日以内の解約ユーザーにインタビュー** → 月2〜3件でも十分

## 事例

### 成功例：Notion的な段階的価格設計

- 無料プランで習慣化 → 有料機能で解約率を下げる「ロックイン」を設計
- 個人開発でもFreemium構造にすることでCAC≒0を実現しやすい
- Churn Rateを3%→1.5%に半減させると、LTVは約2倍になる

### 失敗例：MRR成長に騙される

- 毎月50人新規獲得しても毎月40人解約していれば実質停滞（グロウズ問題）
- ARRが1000万円あっても、LTV/CACが1.2ならスケールするほど赤字が増える
- 解約理由を「価格が高い」と誤解し値下げ→実は機能不足が原因だった

---

## アンチパターン

- **Churnを無視してMRR成長だけ追う**: バケツに穴が開いたまま水を注ぎ続ける
- **CACに自分のコストを含めない**: 個人開発者が最も陥りやすい過小評価
- **LTVを過大に見積もる**: 「将来のアップセル」を含めた予測LTVは使わない。実績ベースで計算
- **Churn改善より新規獲得を優先する**: 既存顧客の解約を1%減らすほうが、広告費を倍にするより効果的なことが多い
