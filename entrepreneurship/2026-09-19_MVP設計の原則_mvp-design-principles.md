# MVP設計の原則：何を作らないか、最小限の検証方法

## 概要

MVPはMinimum Viable Productの略。「最小限の機能で、最大限の学習を得る」が本質。
個人開発者が陥りがちな失敗は「完璧なものを長期間作り続け、ユーザーに届けないまま挫折する」こと。
MVPの目的はプロダクトを完成させることではなく、仮説を検証することにある。
コードを書く前に「これは本当に必要か？」を問い続けることが、1人起業家の最重要スキル。

---

## 核となる考え方

- **MVPは「完成品の小さいバージョン」ではない** → 仮説検証のための実験装置
- **削れるものを削る順序**：機能 → 品質 → 対象ユーザー数 → 対象セグメント
- **「作る前に売れるか」を先に検証する**：ランディングページ → 事前登録 → 支払い → 開発
- **価値仮説と成長仮説を分けて考える**：
  - 価値仮説：このプロダクトはユーザーに価値を与えるか？
  - 成長仮説：どうやってユーザーを獲得・継続させるか？
- **完璧主義はリリースを殺す**：60%の完成度でリリースし、フィードバックで磨く

---

## 実践フレームワーク・ステップ

### STEP 1：解くべき問題を1文で定義する
```
「[ターゲット] は [状況] のとき、[問題] に困っている。
私たちは [解決策] で、[価値] を提供する。」
```

### STEP 2：仮説を3層に分解する
| 層 | 仮説の内容 | 検証方法 |
|---|---|---|
| 問題仮説 | この問題は本当に存在するか？ | ユーザーインタビュー10人 |
| 解決仮説 | この解決策で問題が解けるか？ | プロトタイプ or モック |
| 市場仮説 | 払ってくれる人はいるか？ | 事前登録・先払い |

### STEP 3：MVPの種類を選ぶ
- **コンシェルジュMVP**：手動でサービスを提供しながら需要を検証
  - 例：自動化ツールを作る前に、Slackで手動対応してみる
- **ウィザード・オブ・オズMVP**：ユーザーから見てはAIや自動化に見えるが、裏では人間が動いている
- **ランディングページMVP**：機能なしで申し込みボタンだけ作り、クリック率を計測
- **プロダクトMVP**：本当に最小限のコア機能だけ実装（認証・決済・コア機能のみ）

### STEP 4：MVPに含めない機能リストを作る
「あったら便利」な機能を全部書き出し、**全部削除する**。残るのはコア価値だけ。

```
含める（最大3つ）：[コア機能のみ]
含めない（全部後回し）：通知、ダッシュボード、設定画面、SNS連携、API...
```

### STEP 5：1週間で検証できる形にする
- ランディングページ → 3日で作れる
- コンシェルジュMVP → 1日で始められる
- プロダクトMVP → 1週間以内にリリース判断できるスコープに絞る

## 成功/失敗の事例

### 成功例：Dropboxのスモークテスト
- **実際の行動**：デモ動画（3分）を作っただけ → 一晩で75,000人がメール登録
- **学び**：コードを1行も書かずに「需要があるか」を証明した

### 成功例：個人開発者のSaaSパターン
- NoCode/Zapier組み合わせでMVPを数日で作成 → 10人に使ってもらって有料化を検証 → コードで再実装
- 最初から作り込まず、ツールで繋いで「仮の動くもの」を先に出す

### 失敗例：1年かけて作ったSaaS
- 「完成させてからリリース」の心理で12ヶ月開発 → リリース後、誰も使わなかった
- 問題：ユーザーインタビューなし、市場仮説の検証なし、機能過多

---

## アンチパターン

- **機能多すぎMVP**：「最初からこれくらいは必要」と自分を納得させる → コアの検証が曇る
- **ユーザーなしMVP**：作ってから「さあ誰かに使ってもらおう」 → リリース前にユーザーを持て
- **フィードバックを無視したPDCAループ**：数字を見ずに「次の機能」を追加し続ける
- **MVPを「恥ずかしくないもの」にしようとする**：Reid Hoffman「恥ずかしくなければリリースが遅すぎる」
- **BtoB個人開発の落とし穴**：エンタープライズ機能（SSO、監査ログ）を最初から作る → まず1社に手動提供して検証しろ
- **無料MVP依存**：無料ユーザーしか集めず「価値がある」と思い込む → 課金する人がいるかを早期に確認

## 明日から試せるアクション

1. **今作っているもの（または作ろうとしているもの）の機能リストを全部書き出し、半分以上を「後回し」に移す**
   - 残った機能が3つ以下になれば合格
   - 「なくても最初の価値は伝わるか？」を基準に削る

2. **ランディングページを48時間以内に公開する**
   - Notionページ・Carrd・Framer何でもいい
   - 「メールアドレスを登録」ボタンだけ置いて、10人に見せる
   - クリックが0なら問題/ソリューション仮説を再検討

3. **「コンシェルジュMVP」として手動で1人に提供してみる**
   - 自動化する前に、手作業でサービスを1人に届けてみる
   - その人が「もっと使いたい」「友達に教えたい」と言うか確認する
