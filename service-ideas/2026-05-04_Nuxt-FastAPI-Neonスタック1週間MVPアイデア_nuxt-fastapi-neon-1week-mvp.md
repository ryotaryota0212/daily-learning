# Nuxt + FastAPI + Neon スタックで 1 週間で作れる MVP アイデア

作成日: 2026-05-04
テーマ領域: 9. Nuxt + FastAPI + Neon スタックで1週間で作れるMVPアイデア

---

## 1. はじめに：このスタックを選ぶ理由

「個人開発者が 1 人で土日＋平日夜 = 約 40〜50 時間で MVP を出す」を前提に、
以下の 3 つを組み合わせたスタックの優位性を整理する。

| レイヤ | 採用技術 | 理由 |
|-------|---------|-----|
| フロントエンド | **Nuxt 3 (Vue 3, Nitro)** | SSR/SSG/ISR/Edge を 1 設定で切替可。`useFetch` で型安全な API 呼び出し。Nuxt UI / Nuxt Image など標準 UI ライブラリが揃う。 |
| バックエンド | **FastAPI (Python 3.12)** | Pydantic v2 で型バリデーションが強力。OpenAPI スキーマ自動生成 → Nuxt 側で型をそのまま流用できる。AI/データ処理が混じる用途に強い（LangChain・OpenAI SDK・pandas など）。 |
| DB | **Neon (Serverless Postgres)** | Branching が無料、スケール to zero、`pg_vector` 拡張が標準対応。スキーマ変更を試す PoC フェーズに最適。 |
| 補助 | Vercel (Nuxt) / Fly.io or Railway (FastAPI) / Clerk or Supabase Auth | デプロイ・認証を「自前で書かない」ことを徹底 |

**この組み合わせの強み**

1. **AI 系機能との相性**：FastAPI で OpenAI / Anthropic / 埋め込み生成、Neon の `pg_vector` でベクトル検索、Nuxt でリアクティブな UI、という三段構えが少ない設定数で完結する。
2. **スキーマブランチング**：Neon の DB ブランチを Vercel のプレビューデプロイ単位で分けられるので、本番を壊さず壊しながら開発できる。
3. **TypeScript ⇄ Python の摩擦が最小**：FastAPI が出力する `openapi.json` から `openapi-typescript` で型を生成し、Nuxt の `$fetch` に渡すと、フロント側でも完全型付け。

以下、上記スタックで「実際に 1 週間（約 40〜50 時間）で動くデモまで持っていける」アイデアを 5 つ提案する。
すべて **個人開発者 1 人**を前提に、想定ユーザー / 収益モデル / 1 週間のスプリント計画 / 差別化ポイント / 実現可能性スコアを付与する。

## 2. アイデア 1：『議事録カットアップ』 — 1 時間の Zoom 録画から「役員報告 5 分動画」を生成

### 概要

1 時間の社内会議録画をアップロードすると、
（a）話者ダイアライゼーション → （b）AI が要点抽出 → （c）該当部分の動画クリップを自動でつなぎ、
**役員・他部署向けのダイジェスト動画 5 分（字幕＋話者アイコン入り）** を出力する SaaS。

### 想定ユーザー

- 中堅 SaaS / 受託開発企業の PM・PMO
- マネジメント職向けに「会議の要点を共有しろ」と言われているが、毎回テキスト議事録だけでは伝わらない層
- 日本語の会議が多く、欧米製 (Otter, Fireflies) では精度・UX が物足りない層

### 収益モデル

- フリーミアム：月 30 分まで無料 → 個人で「使い心地」をまず体験
- Pro：月 ¥1,980 / 10 時間まで
- Team：月 ¥4,980 / ユーザー / 50 時間まで（SSO は将来）

### 技術スタック

- フロント：Nuxt 3 + Nuxt UI + Plyr (動画プレイヤー)
- バック：FastAPI + Celery (or arq) + ffmpeg-python
- AI：
  - 文字起こし：Whisper large-v3-turbo（自前 GPU 不要、Replicate or OpenAI Whisper API）
  - 話者分離：pyannote.audio (CPU でも 1 時間 ≒ 5 分)
  - 要約：Claude Haiku 4.5（コスト面で最適、長文要約が得意）
- DB：Neon（メタデータ・ジョブ状態・ユーザー）
- ストレージ：Cloudflare R2（エグレス無料が決め手）

### 差別化ポイント

- 既存サービス（Otter, tldv, Fireflies）は「テキスト要約」止まり。**動画クリップを切ってつなぐ**プロダクトはまだ少ない。
- 日本語の敬語・社名・人名にチューニング（プロンプトと辞書で）。
- 「報告動画」という具体的なアウトプット名で UI を揃え、用途を絞る。

### 1 週間スプリント計画

| 日 | タスク | 時間 |
|---|------|-----|
| 月 | Nuxt + FastAPI + Neon プロジェクト雛形、Clerk 認証、R2 アップロード | 6h |
| 火 | Whisper API + pyannote のジョブ実行を arq で非同期化 | 7h |
| 水 | Claude へ「見出し＋タイムスタンプ」を JSON で要求、ffmpeg で切り出し | 8h |
| 木 | 動画連結＋字幕焼き込み、サムネイル生成 | 7h |
| 金 | 視聴 UI、共有リンク、課金（Stripe Checkout） | 7h |
| 土 | LP、デモ動画、Product Hunt / X 投稿準備 | 6h |
| 日 | β ローンチ、Slack コミュニティで紹介 | 4h |

### 実現可能性

- **技術難度：中**（音声処理ライブラリの依存関係が地雷になりやすい。Docker で固める）
- **コスト：1 時間動画あたり ≒ ¥30〜50**（Whisper API + Claude Haiku）。粗利は十分確保可能。
- **個人開発で作れるか：◯**（ffmpeg のオプションだけ事前に手元検証しておけば 1 週間で β は十分到達）

## 3. アイデア 2：『SaaS Changelog Watcher』 — 競合 SaaS の更新を毎朝 Slack に届ける

### 概要

ユーザーが「監視したい SaaS」を URL で登録すると、対象の changelog ページ・Twitter アカウント・GitHub releases を毎日クロールし、
**「あなたのプロダクトに関係しそうな差分」を AI が抽出して Slack / Discord / メールに毎朝 9 時に届ける**サービス。

### 想定ユーザー

- BtoB SaaS の PM / プロダクトマーケ
- 競合分析を週次でやっているが、毎回手動で見に行くのが苦痛な人
- 投資家・SaaS リサーチャー

### 収益モデル

- 個人：月 ¥980 / 監視 5 サービス
- ビジネス：月 ¥4,980 / 監視 30 サービス + Slack 連携 + 共有ダッシュボード
- API プラン：月 ¥19,800〜（情報配信エージェントへの再販想定）

### 技術スタック

- フロント：Nuxt 3 + Nuxt Content（自前メディアも兼ねられる）
- バック：FastAPI + Playwright（クロール）+ Apscheduler
- AI：Claude Haiku で「自社プロダクト概要 vs 競合差分」を比較、関連度スコア化
- DB：Neon（差分履歴を `tsvector` + `pg_vector` で全文＋意味検索）
- 通知：Slack Incoming Webhook / Resend (メール) / Discord Webhook

### 差別化ポイント

- 既存ツール（Feedly + AI 要約）は「カテゴリで一括」のため**自社にとって関係あるかが分からない**。
- 「あなたのプロダクト概要」を 1 度書かせて、関連度フィルタする点が肝。
- Nuxt Content で「公開可能な変更ログ」をそのまま自社メディアにできる、というオマケ機能。

### 1 週間スプリント計画

| 日 | タスク | 時間 |
|---|------|-----|
| 月 | プロジェクト雛形、Auth、サービス登録 CRUD | 6h |
| 火 | Playwright で changelog スクレイピング基盤、cron 実装 | 7h |
| 水 | 差分抽出 → Claude へ「自社概要との関連度」プロンプト | 7h |
| 木 | Slack / メール配信、ダッシュボード | 7h |
| 金 | Stripe 課金、ベクトル検索 UI | 6h |
| 土 | LP、Indie Hackers 投稿用ストーリー作成 | 6h |
| 日 | β 配布、Slack の Indie 系コミュニティで告知 | 4h |

### 実現可能性

- **技術難度：低〜中**（スクレイピング対象を 50 件くらいに絞れば運用が回る）
- **個人開発で作れるか：◎**（Cron + LLM + 通知は最も「型」化しやすい）
- **リスク**：robots.txt 違反のサイトを対象にしないこと。RSS / 公式 API がある相手を優先。

## 4. アイデア 3：『Receipt to Freee』 — レシート画像から freee / マネーフォワード仕訳 CSV を生成

### 概要

スマホで撮ったレシート / 領収書 PDF をドラッグ&ドロップすると、
科目推定・税率振り分け・取引先名の正規化まで AI で行い、
**freee / マネーフォワード / 弥生 にインポート可能な CSV** を出力する。

### 想定ユーザー

- 一人法人・フリーランス（**現状の freee / MF の AI 自動仕訳に不満**な層）
- 月 100〜500 件の領収書をさばく税理士事務所のアシスタント
- 既存サービスは「金額」と「日付」は読むが、「科目選定」は人間頼みなのが課題

### 収益モデル

- 100 枚 / 月まで無料
- 個人：月 ¥1,480 / 1,000 枚
- 事務所：月 ¥9,800 / 10,000 枚 + マルチクライアント切替

### 技術スタック

- フロント：Nuxt 3 + Vue Drag-and-drop + Nuxt PWA
- バック：FastAPI + pdf2image + Pillow
- AI：
  - OCR：Claude Sonnet 4.6 のマルチモーダル（手書き含めて精度が高い）
  - 科目推定：過去仕訳を Neon の `pg_vector` に埋め込み、k-NN で類似仕訳から推定
- DB：Neon
- 出力：freee CSV / MF CSV / 弥生 CSV テンプレートを Pydantic モデルで定義

### 差別化ポイント

- 既存の freee 自動仕訳は「学習データが新規ユーザーには蓄積されていない」ため精度が低い。
- 本サービスは **「同業種の匿名仕訳データ」**を埋め込みベースで参照することで、登録初日から 80% 以上の正解率を狙う。
- freee / MF の API に**書き込まない**（連携審査が重い）。CSV 出力に絞ることで個人でも作りきれる。

### 1 週間スプリント計画

| 日 | タスク | 時間 |
|---|------|-----|
| 月 | UI（D&D, プレビュー）、Auth、Stripe | 7h |
| 火 | Claude マルチモーダル OCR + プロンプト | 7h |
| 水 | 科目マスタ取込、`pg_vector` で類似仕訳検索 | 7h |
| 木 | CSV エクスポート（freee, MF, 弥生それぞれの仕様） | 6h |
| 金 | バッチ処理 UI、エラー再処理 | 6h |
| 土 | LP（税理士向けと個人向けで 2 種類） | 6h |
| 日 | β 配布、note で「仕訳精度実測」記事公開 | 4h |

### 実現可能性

- **技術難度：中**（ふるい OCR ではなく LLM マルチモーダルに振り切ることで実装は簡素）
- **個人開発で作れるか：◯**（freee / MF の CSV 仕様調査が地味に時間を食う）
- **コスト**：Claude Sonnet マルチモーダル 1 枚 ≒ ¥3〜5。¥1,480 で 1,000 枚は粗利率 60% 以上。

## 5. アイデア 4：『デザイン PR 自動コメント Bot』 — Figma の差分を GitHub PR に貼る

### 概要

GitHub の PR タイトル / ブランチ名に `figma:<file_id>/<frame_id>` と書くと、
（a）Figma API でフレーム画像を取得 → （b）main 側のフレームと差分を画像比較 → （c）「変更点をテキスト化」した上で **GitHub PR にコメントする Bot**。

### 想定ユーザー

- 5〜30 人規模の Web プロダクトチーム
- デザイナとエンジニアの「言った言わない」を減らしたい PM
- Figma を「仕様書」として運用しているが、レビュー時に Figma を開かない人が多いチーム

### 収益モデル

- リポジトリ 3 つまで無料
- Pro：月 $19 / org（無制限リポジトリ、Slack 通知）
- Team：月 $49 / org（複数 Figma ファイル、画像差分の容量増）

### 技術スタック

- フロント：Nuxt 3（管理ダッシュボードのみ、最小限）
- バック：FastAPI + GitHub Webhook receiver + Figma REST API
- 画像差分：Pillow + scikit-image (`structural_similarity`) → 差分領域抽出
- 自然言語化：Claude Sonnet 4.6（マルチモーダルで「左:before / 右:after」を渡す）
- DB：Neon（org / installation / 履歴）

### 差別化ポイント

- Figma 公式の「Branching」は有料プラン限定。**Free / Starter プランの Figma でも使える差分ビューア**としての価値。
- 既存の Pixel Diff 系（Percy, Chromatic）は実装後の UI を比較するもの。**デザイン段階の差分**を扱うものはまだ少ない。
- GitHub Marketplace へ出すと初期流入を稼ぎやすい。

### 1 週間スプリント計画

| 日 | タスク | 時間 |
|---|------|-----|
| 月 | GitHub App セットアップ、Webhook 受信、Auth | 7h |
| 火 | Figma API トークン管理、フレーム画像取得 | 6h |
| 水 | 差分検出（SSIM）、領域抽出 | 7h |
| 木 | Claude へマルチモーダルで送信、コメント文生成 | 6h |
| 金 | PR コメント投稿、ダッシュボード（履歴） | 7h |
| 土 | Stripe、GitHub Marketplace 申請準備、LP | 6h |
| 日 | β、Dev.to / Zenn に技術記事 | 4h |

### 実現可能性

- **技術難度：中〜高**（GitHub App の権限設計と Figma API レート制限が地雷）
- **個人開発で作れるか：△〜◯**（Marketplace 申請に時間がかかるため、最初は GitHub Action として配布する手も）
- **市場性**：類似カテゴリで成功例（Linear → GitHub 連携、Cursor の PR レビュー Bot）が出ており、ニーズは確実。

## 5. アイデア 5：『地域コミュニティ AI 受付係』 — 商工会議所 / 地域団体向けの問い合わせ AI

### 概要

地方の商工会議所・観光協会・町内会が運営するサイトに**「24 時間受付の AI チャット」**を埋め込めるサービス。
PDF / Word の規約・案内文をドラッグするだけで RAG が組める。
回答できない問い合わせは LINE / メールで担当者に転送。

### 想定ユーザー

- 地方の商工会議所、観光協会、移住相談窓口、社協、PTA、地元 NPO
- 「電話対応で日中の業務が止まる」が、専任のチャット担当を雇う予算はない団体

### 収益モデル

- 月 ¥3,980（FAQ 50 件まで、月 1,000 件チャット）
- 月 ¥9,800（FAQ 無制限、月 10,000 件、LINE 公式アカウント連携）
- 自治体パッケージ：年 ¥120,000〜（請求書払い対応）

### 技術スタック

- フロント：Nuxt 3 + 埋め込み用 Web Component（`defineCustomElement`）
- バック：FastAPI + LangChain ではなく素の RAG（ライブラリ依存を減らす）
- AI：
  - 埋め込み：OpenAI text-embedding-3-small（コスト面）
  - 回答：Claude Haiku 4.5（日本語回答品質と単価のバランス）
- DB：Neon + `pg_vector`
- 通知：LINE Messaging API、Resend

### 差別化ポイント

- 既存チャットボット (ChatPlus 等) は月 ¥15,000 〜と高く、機能過多で地方団体には使われていない。
- **「請求書・銀行振込・年契約」**に標準対応する個人開発 SaaS は少なく、地方公共系市場と相性が良い。
- 自治体の「電子申請ポータル」連携テンプレートを 5 つ用意して横展開（観光協会 → 商工会議所 → 町内会）。

### 1 週間スプリント計画

| 日 | タスク | 時間 |
|---|------|-----|
| 月 | プロジェクト雛形、Auth、テナント設計 | 6h |
| 火 | PDF/Word 取り込み → 埋め込み生成 → Neon 投入 | 7h |
| 水 | RAG クエリ、ストリーミング応答 | 7h |
| 木 | 埋め込み Web Component、サイト埋込検証 | 7h |
| 金 | LINE / メール転送、管理画面（履歴 / FAQ 編集） | 7h |
| 土 | LP（自治体向け）、請求書 PDF 自動発行 | 6h |
| 日 | デモ環境準備、地元商工会議所にアポ取り | 4h |

### 実現可能性

- **技術難度：低**（RAG のテンプレ実装で十分、UI が肝）
- **個人開発で作れるか：◎**（技術より「営業の足」が必要。営業を兼業できる開発者向け）
- **市場規模**：日本の商工会議所 515 + 観光協会 1,000 超 + 町内会数万。客単価が小さくても十分回る。

## 7. 1 週間 MVP を成功させる「型」テンプレ

このスタックで個人開発する際に、どのアイデアでも共通して有効な進め方。

### Day 0（事前準備、半日）

- Neon でプロジェクト作成し `main` / `dev` / `preview` の 3 ブランチを切る
- Vercel に Nuxt の空プロジェクトをデプロイし、Preview Deploy を Neon `preview` に紐付け
- Fly.io / Railway に FastAPI の空アプリ（`/healthz` だけ）を上げ、ログ・メトリクスを確認
- Stripe / Clerk / Resend / Sentry のアカウントだけ作って `.env` に並べておく

### Day 1〜2（コア体験を 1 本道で動かす）

- DB スキーマは最小（ユーザー、コア entity、ジョブの 3 テーブル程度）
- フロントのページは「ランディング」「ダッシュボード」「詳細」の 3 つだけ
- **認証・課金は最後**。とにかくダミーユーザーで E2E が通るのを優先

### Day 3〜4（AI 部分を磨く）

- プロンプトは Claude / OpenAI のどちらが良いか実データで A/B
- LLM 出力は **Pydantic モデルに schema 強制**して、フロント側の型と一致させる（`response_format` / function calling）
- 失敗時のフォールバック（リトライ、別モデル）を 1 段だけ用意

### Day 5（収益化＆運用）

- Stripe Checkout（Subscription）を 1 プランから
- Sentry でエラー / Slack 通知
- 利用量メータリング（簡素に Neon 上の counter テーブルで OK）

### Day 6〜7（出す・聞く）

- LP は Nuxt の `pages/index.vue` に 1 ページ。動画 30 秒。
- Product Hunt / Indie Hackers / X / Zenn のどれか 2 つで露出
- 翌週月曜の朝までに **3 人の有料ユーザーから feedback** を集めるまで完了とする

## 8. このスタックの落とし穴と対策

| 落とし穴 | 症状 | 対策 |
|---|---|---|
| Nuxt の SSR で Pinia の hydration エラー | 本番だけ画面が真っ白 | `useState` で SSR 対応の状態管理、`<ClientOnly>` 適切に |
| FastAPI の async 周り | `pyannote` などが同期で詰まる | I/O は `httpx.AsyncClient`、CPU 重い処理は arq / Celery で別プロセス |
| Neon のスケール to zero | 初回アクセスがコールドスタート（1〜2 秒） | フロントの読み込み時に `/healthz` をサイレント叩きで温める |
| OpenAPI 型生成のズレ | フロントとバックの型が突然壊れる | CI で `openapi-typescript` を実行、差分が出たら fail |
| LLM コストの暴発 | 月初に予算溶ける | ユーザー単位のクォータをミドルウェアで制御、`max_tokens` 固定 |

## 9. 結論

- Nuxt + FastAPI + Neon は **「AI を絡めた SaaS を 1 人で 1 週間で出す」**用途で 2026 年現在の最適解の 1 つ。
- 5 アイデアのうち、**営業がいらず技術で完結する案 (②)** と **競合不在のローカル市場案 (⑤)** が、個人開発者の 3 ヶ月後 MRR 確度が最も高い。
- どのアイデアでも **「Day 0 のインフラ準備を半日で終わらせる」**ことが 1 週間 MVP 成功の最大の鍵。
- 共通教訓：**認証・課金・LP は最後**。Day 5 まではコア体験 (AI を含む 1 本道) に時間を集中させる。
