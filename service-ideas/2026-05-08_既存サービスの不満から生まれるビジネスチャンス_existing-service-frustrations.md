# 既存サービスの不満から生まれるビジネスチャンス

作成日: 2026-05-08

---

## 市場概要

「不満こそが最良のプロダクトアイデアの源泉」という原則は、スタートアップの世界で繰り返し実証されている。Slack（メールの不満）、Notion（複数ツールの分散）、Figma（Sketchのコラボ不足）など、多くのヒットサービスは既存サービスへの具体的な不満から生まれた。

### 現在の不満集積源
- Reddit/X での「〇〇の代替を探している」系スレッド
- App Store / Google Play の低評価レビュー
- Twitter/X のツール愚痴ツイート（#nocode #SaaS タグ）
- HN の「Ask HN: What are you building?」スレッド
- 日本では Zenn / Qiita の「〇〇が辛い」系記事

## 具体的なサービスアイデア

### 1. SlackBot地獄からの脱出ツール「BotSweeper」

**背景となる不満**
- Slack に Bot が増えすぎて通知が意味をなさない
- どの Bot が何をしているか管理者すら把握できない
- 不要 Bot の削除が怖くてできない

**想定ユーザー**
- Slack を使う 30〜200 名規模のスタートアップ・IT企業の Slack 管理者

**収益モデル**
- Freemium: Bot 10 個まで無料、以降 $9/月
- Team プラン: $29/月（Bot 無制限 + アラート機能）

**技術スタック**
- Slack API + Bolt for Python / FastAPI
- Neon（Bot 使用履歴の保存）
- Nuxt 3（管理ダッシュボード）

**差別化ポイント**
- Bot ごとの「最終使用日」「発火回数」「コスト試算」を可視化
- 安全な削除手順を提案する AI アシスト機能

**個人開発可能性: ★★★★☆**
- Slack API の習熟が必要だが、OAuth + Webhook の実装は週末 2〜3 日で完了可能
- MVP は管理画面なしで Slack コマンドだけでも成立する

---

### 2. Notion テンプレート疲れ解消ツール「TemplateSync」

**背景となる不満**
- Notion テンプレートを購入したが、自社フローに合わせる改修が大変
- チームで使うと誰かが構造を壊す
- テンプレートのバージョン管理ができない

**想定ユーザー**
- Notion を業務利用している 5〜50 名のチーム（PMO・総務担当者）

**収益モデル**
- $15/月/ワークスペース（無料トライアル 14 日）
- テンプレートマーケット手数料 20%（将来的な収益柱）

**技術スタック**
- Notion API + Python（差分検出ロジック）
- FastAPI（バックエンド）
- Neon（スナップショット保存）
- Nuxt 3（差分ビューア UI）

**差別化ポイント**
- Git のような「テンプレートの diff 表示とロールバック」
- 「保護ブロック」指定で誰が編集してもコアを守る

**個人開発可能性: ★★★☆☆**
- Notion API のブロック構造の深い理解が必要
- 差分検出アルゴリズムが技術的ハードル。ただし JSON diff ライブラリで代替可能

### 3. Zoom 録画の「見ない問題」を解決する「MeetBrief」

**背景となる不満**
- Zoom 録画が溜まる一方で誰も見ない
- AI 文字起こしはあるが「で、何が決まったの？」がわからない
- 欠席者が「あとで録画見ます」と言って見ない

**想定ユーザー**
- リモートワーク中心の企業（エンジニア・デザインチーム）
- 週 5 回以上の会議がある 10〜100 名規模のチーム

**収益モデル**
- $12/ユーザー/月（5ユーザー以上から）
- 録画時間従量課金オプション（大企業向け）

**技術スタック**
- Zoom Webhook + Zoom Cloud Recording API
- Whisper API（文字起こし）+ Claude API（要約・決定事項抽出）
- FastAPI + Neon（録画メタデータ管理）
- Nuxt 3（ダッシュボード）+ Slack Webhook（通知）

**差別化ポイント**
- 「決定事項」「アクションアイテム」「未解決の議論」を自動タグ分類
- Slack に 3 行サマリーを自動投稿し「見なくてもわかる」状態にする
- 欠席者だけに通知する「あなたが不在だった会議」機能

**個人開発可能性: ★★★★☆**
- Zoom API + Whisper + LLM の組み合わせはすでに枯れた技術
- MVP は Slack 通知だけに絞れば 1 週間以内にリリース可能

### 4. サブスク管理アプリの「解約できない問題」を解く「CancelKit」

**背景となる不満**
- サブスクを解約しようとすると引き止め UI（ダークパターン）で諦める
- 解約手順が複雑すぎて時間がかかる
- 気づいたら課金され続けている SaaS が複数ある

**想定ユーザー**
- SaaS を多数契約している個人開発者・フリーランス・スタートアップ創業者

**収益モデル**
- 無料: 5サービスまで追跡
- Pro $8/月: 無制限追跡 + 解約手順ガイド + 更新前アラート

**技術スタック**
- FastAPI + Neon（契約情報管理）
- Nuxt 3（ダッシュボード）
- メール解析（Gmail API / IMAP）で自動検出

**差別化ポイント**
- 各サービスの解約手順をデータベース化（コミュニティ投稿型）
- 「このサービスの解約難易度: 難」などのスコア表示
- 更新 7 日前に Slack / LINE 通知

**個人開発可能性: ★★★★★**
- DB と通知だけなら 3 日で MVP 完成
- コミュニティデータが差別化になるのでネットワーク効果も期待できる

## 実現可能性の総合評価

| アイデア | 技術難度 | 市場規模 | 競合 | 個人開発 | 総合 |
|---|---|---|---|---|---|
| BotSweeper | 中 | 中 | 少 | ◎ | A |
| TemplateSync | 高 | 中 | 少 | △ | B |
| MeetBrief | 低〜中 | 大 | 多 | ○ | B+ |
| CancelKit | 低 | 中〜大 | 中 | ◎ | A |

### 最も推奨: CancelKit

- 技術的に最もシンプルで 1 週間 MVP が現実的
- 「解約できない怒り」は強い感情 → バイラル拡散しやすい
- Pro プランへのアップグレード動機が明確
- Nuxt + FastAPI + Neon スタックにほぼ完全にフィット

### 次点: BotSweeper

- Slack 利用企業の Pain がはっきりしている
- 管理者権限で導入されるため解約率が低い（B2B の強み）
- AppDirectory への掲載でオーガニック流入が見込める

---

## まとめ

既存サービスへの不満をビジネスにする際の鉄則は「不満の強度」と「技術的シンプルさ」のバランスを取ること。強い不満があっても実装が複雑すぎると個人開発では完走できない。CancelKit と BotSweeper はどちらもこのバランスが取れており、2026 年現在でも競合が少ない穴場領域と言える。
