# Nuxt + FastAPI + Neon スタックで1週間で作れるMVPアイデア

作成日: 2026-05-01

## テーマタイトル
個人開発者が「Nuxt 3 (Vue) + FastAPI (Python) + Neon (Serverless Postgres)」というモダンで軽量なスタックを使って、約1週間（7日間 / フルタイム換算で40〜60時間）で立ち上げられる現実的なMVPアイデアの分析。

## 市場概要

### なぜこのスタックなのか
- **Nuxt 3**: SSR / SSG / SPA を切り替え可能。Vercel・Cloudflare Pages・Netlifyに数クリックでデプロイ可能。SEOが効くフロントを少人数で作るのに向いている。
- **FastAPI**: 型ヒントベースで自動的にOpenAPIドキュメントが生成される。Python資産（LLM、データ分析、PDF処理、音声処理）と直結できるのが最大の強み。
- **Neon**: Serverless Postgresで、ブランチ機能とスケールゼロにより無料枠でも本番運用が現実的。Pgvector拡張をサポートしているのでRAG系アプリにも使える。
- これらは「2025〜2026年に個人開発者が選びがちなスタック」として急速に標準化しており、Render / Railway / Fly.io などのPaaSとも相性が良い。

### 1週間MVPの制約条件
- バックエンドの認証はClerk / Auth.js / Supabase Auth等のマネージド認証を借りる前提（自前実装は1日では終わらない）。
- 決済はStripe Checkout（リダイレクト型）に統一し、サブスクは月額単一プランから始める。
- メール送信はResend、ファイル保存はCloudflare R2かUploadThingに寄せ、自前のS3構成は避ける。
- 「LLM呼び出し」を主役にする場合、初期はOpenAI / Anthropicのマネージド推論一択（GPU運用は1週間に収まらない）。

### 1週間で作れるMVPの要件分解（共通）
- 1〜2日目: スキーマ設計（Neonにブランチを切る）+ FastAPIのCRUDエンドポイント生成 + Nuxtの認証導入
- 3〜4日目: コア機能（差別化ポイントになる1つだけ）の実装
- 5日目: 課金導線とランディングページ
- 6日目: 自動テスト・E2Eシナリオ・エラートラッキング（Sentry無料枠）
- 7日目: バグ修正、ドメイン接続、Product Hunt / X(旧Twitter)向けのデモ素材作成

## 具体的なサービスアイデア

### アイデア1: 「議事録から次アクションを抽出するSlack拡張」 — MeetingToDo
社内ミーティングのZoom/Google Meetの録音または文字起こしをアップロードすると、FastAPI側でLLMが「ToDo・期限・担当者」を抽出し、Slack上に自動投稿。週次ダイジェストもメール配信する。

- **想定ユーザー**: 10〜100名規模のスタートアップ、リモート中心のチーム、PMが議事録を整える時間を奪われている組織。
- **収益モデル**: SaaSサブスク。$15/ユーザー/月（チームプラン、5シートから）。Free枠は「録音3本/月まで」。
- **技術スタック**:
  - フロント: Nuxt 3 + UnoCSS、Slack OAuthはNuxtのサーバールートで処理
  - バック: FastAPI + Celery（Redis）で文字起こしジョブを非同期処理。Whisper APIで文字起こし、Claude / GPTで構造化抽出
  - DB: Neon（meetings, action_items, integrationsの3テーブル中心）
  - 配信: Slack Incoming Webhook + Resend
- **差別化ポイント**: 既存の「議事録AI」は要約止まりが多い。本サービスはあくまで「次アクション」だけに集中し、Slack上で担当者へDMしてリマインドまで行う「実行支援」に特化する。
- **1週間MVP適性**: ★★★★☆ 文字起こしとSlack OAuthの組み合わせがやや重いが、既存ライブラリ（slack-sdk、faster-whisperは使わずWhisper API）で7日に収まる。

### アイデア2: 「個人事業主向け 経費レシートのPDF整理係」 — ReceiptVault
日本の個人事業主・フリーランスが年末に直面する「電子帳簿保存法対応」の地獄を、Nuxtのドラッグ&ドロップUIとFastAPIのOCR処理で半自動化。レシート画像をアップロードすると、日付・金額・取引先・勘定科目が抽出され、月別フォルダにPDFとして整理される。

- **想定ユーザー**: 売上1,000万円未満の個人事業主、フリーランスエンジニア、副業サラリーマン。会計ソフト（freee / 弥生）を使うほどではないが、Excel管理に限界を感じている層。
- **収益モデル**: 年額買い切り（¥4,800/年）+ クラウド保存オプション（¥980/月）。確定申告期前の1〜3月に集中して売る。
- **技術スタック**:
  - フロント: Nuxt 3 + PWAモジュール（スマホで撮影 → そのまま登録できるUX）
  - バック: FastAPI + Google Cloud Vision OCR + Claude Haikuで勘定科目分類
  - DB: Neon（receipts, categories, monthly_summariesの3テーブル）
  - ストレージ: Cloudflare R2に原本画像 + 生成PDFを格納
- **差別化ポイント**: freee / マネーフォワードは「会計ソフト」の文脈で売られているが、本サービスは「電子帳簿保存法のためだけのストレージ」というポジショニングで価格を抑える。確定申告書は作らない、と割り切る。
- **1週間MVP適性**: ★★★★★ OCRがマネージドAPIで済むため、開発工数の8割はUIに使える。日本市場の課題が明確で、初期ユーザー獲得もnoteやXで集めやすい。

### アイデア3: 「ニッチRSSの個人キュレーション通知」 — NicheRadar
「半導体業界の人事異動だけ」「日本酒の新銘柄だけ」「AIフレームワークのv1.0リリースだけ」のような、超ニッチな観点で複数RSS / Web / Redditを横断してLLMが関連度判定し、毎朝メールでダイジェストを送る。

- **想定ユーザー**: 業界アナリスト、VC、特定領域に深い興味を持つマニア・コレクター、BtoB営業職。
- **収益モデル**: フリーミアム。Free=1トピック・週1配信、Pro=$8/月で最大10トピック・毎日配信、Team=$29/月で共有ダッシュボード。
- **技術スタック**:
  - フロント: Nuxt 3 (SSGでLP+ダッシュボード)
  - バック: FastAPI + APScheduler（cron用）+ Playwrightで一部のJSサイトをスクレイプ
  - DB: Neon (Pgvector拡張)。記事埋め込みでトピック関連度を計算
  - LLM: Claude Haikuで安価にスコアリング（1記事あたり<$0.001）
- **差別化ポイント**: Feedlyは「RSSリーダー」として汎用、Bensbites等は「AI業界専用」のプリセット型。本サービスは「あなたの言葉で1行記述するだけで専用トピックが作れる」点が中核。LLMが関連度を毎朝再評価するため、ニュースの粒度がパーソナライズされ続ける。
- **1週間MVP適性**: ★★★★☆ クロール対象を最初はRSS+Reddit APIに絞れば1週間で動く。最大の難所はメール配信のスパム判定対策（SPF/DKIM/Resend設定）。

### アイデア4: 「個人ブログ向けA/Bテスト型タイトル生成器」 — TitleSplit
個人ブログ・noteの著者が、記事公開前に「3つのタイトル候補をLLMが生成 → 1週間SNS広告で各$5ずつテスト → CTRが高い1本を残す」を完全自動化するツール。

- **想定ユーザー**: noteで月3本以上書く有料記事クリエイター、SubstackライターでマネタイズしているKOL、コンテンツマーケター個人。
- **収益モデル**: 月額$19のサブスク + 広告予算の上乗せ（pass-through）。
- **技術スタック**:
  - フロント: Nuxt 3 + 認証はGoogle OAuthのみ
  - バック: FastAPI + X(旧Twitter) Ads API / Meta Marketing API連携
  - DB: Neon（articles, title_variants, ad_resultsの3テーブル）
  - LLM: Claude Sonnetでタイトル案生成、A/B結果を強化学習風に蓄積
- **差別化ポイント**: 既存のSEOツール（Ahrefs / SEMrush）は検索流入の最適化に寄っているが、本サービスは「ソーシャル流入のタイトル」に特化。実費で実トラフィックを当ててから採用する点が新しい。
- **1週間MVP適性**: ★★★☆☆ 広告APIの審査・連携が個人開発のボトルネック。MVP版は「A/Bテストせず、LLMで5案生成し採点理由を出すだけ」に絞れば1週間で出せる（その後、広告連携を段階追加）。

### アイデア5: 「副業エンジニア向け 工数記録&請求書発行」 — InvoiceLite
副業エンジニア・フリーランスがGitHubのcommitとカレンダーから工数を自動推定し、月末に請求書PDFを生成・送付するシンプルツール。日本の消費税・源泉徴収・インボイス番号にきちんと対応する。

- **想定ユーザー**: 副業エンジニア、業務委託でクライアントを2〜5社抱えるフリーランス、リモートで動く個人デザイナー。
- **収益モデル**: 月額¥1,480。クライアント数3社まで無料、それ以上は課金。
- **技術スタック**:
  - フロント: Nuxt 3 + Vue PDF (vue-pdf-embed) でプレビュー
  - バック: FastAPI + GitHub App + Google Calendar API
  - DB: Neon (clients, projects, time_entries, invoices)
  - PDF生成: WeasyPrint or ReportLab（FastAPI内で完結）
- **差別化ポイント**: マネーフォワードクラウド請求書、freee請求書はあるが、「インボイス対応 + GitHub連携 + 個人レベルの安さ」を全部満たすものは少ない。「請求書だけ」に振り切ることで月¥1,480を実現する。
- **1週間MVP適性**: ★★★★★ ロジックが決定的（時間集計とPDF生成）でAIへの依存が低いため、1週間以内に高い完成度で出しやすい。日本特化のためローカライズも自前でできる。

## 実現可能性の評価

### 1週間で作れるかの観点で5案を比較

| アイデア | 技術難度 | 法務・規制リスク | 1週間MVP適性 | 個人開発者の単独実装可能性 |
| --- | --- | --- | --- | --- |
| MeetingToDo | 中（音声処理） | 低（録音は同意前提） | ★★★★☆ | 可能。Slack OAuthで1日かかる |
| ReceiptVault | 低〜中 | 中（電帳法の解釈ミス） | ★★★★★ | 可能。要件が明確 |
| NicheRadar | 中（クロール多様性） | 中（スクレイピングのToS） | ★★★★☆ | 可能。RSS+Redditに絞れば容易 |
| TitleSplit | 高（広告API） | 低 | ★★★☆☆ | 1週間では広告連携が間に合わない |
| InvoiceLite | 低 | 中（インボイス番号） | ★★★★★ | 可能。最も再現性が高い |

### 個人開発者が1人で作れるかの総合判断
- **最も推奨**: 「ReceiptVault」と「InvoiceLite」。日本の制度（電帳法・インボイス）という参入障壁があり、海外勢が入って来づらい。技術的にも「マネージドOCR + DB + PDF生成」だけで1週間に収まる。
- **次点**: 「NicheRadar」はFree→Pro転換が見込みやすく、マーケがX上で完結する。
- **要注意**: 「TitleSplit」は広告APIとそのレビュー期間（Meta Marketing APIは2週間以上かかる）が個人開発者の最大の敵になる。1週間MVPからは外して、フェーズ2に置くのが現実的。
- **共通の落とし穴**:
  1. **Neonの無料枠**: 同時接続数の上限が低いので、FastAPI側で必ずコネクションプール（asyncpg + pgbouncer互換URL）を使う。
  2. **FastAPIのデプロイ**: Vercelには載らないため、Render or Fly.io無料枠を使う前提でドキュメントを書く。
  3. **Nuxt 3のSSR**: Cloudflare Pagesにデプロイする場合、APIルートのNode依存（fs等）に注意。

### マーケティング適合性
- 1週間で作る前提なので、「Product HuntにLaunchして月$500のARRに到達する」を最初の到達点に置く。
- 日本市場では note + X 経由の流入を主導線にし、英語圏狙いの場合は Indie Hackers / Hacker News を主導線にする。
- どのアイデアも「既存大手が触らないニッチ」を選んでいるため、SEO競合が薄く、個人ブランドの長文記事だけで初期ユーザー獲得が可能と判断する。
