# Nuxt + FastAPI + Neon スタックで1週間で作れるMVPアイデア

作成日: 2026-04-30

## テーマ概要

個人開発者にとって最大のボトルネックは「アイデアを動くプロダクトに変えるまでの時間」である。
MVP を 1 週間以内にローンチできれば、市場検証のサイクルを高速化でき、サブスク課金や Stripe 連携を組み込んでも 2 週間以内に有料顧客を取る目標が現実的になる。

本ドキュメントでは、以下の技術スタックを前提として、1 週間（実働 30〜40 時間）で MVP を完成できるサービスアイデアを 4 つ提示する。

### 想定スタック
- **フロントエンド**: Nuxt 3（SSR + Vue 3 + TypeScript）
  - UI: shadcn-vue + TailwindCSS
  - 認証: nuxt-auth-utils（OAuth）
- **バックエンド**: FastAPI（Python 3.12 + Pydantic v2）
  - ORM: SQLModel
  - 非同期ジョブ: Celery + Redis（必要時のみ）
- **データベース**: Neon（サーバーレス Postgres、ブランチング機能つき）
- **デプロイ**: フロント=Vercel / Cloudflare Pages、バックエンド=Fly.io または Render
- **決済**: Stripe Checkout + Customer Portal
- **その他**: Resend（メール）、PostHog（分析）、Sentry（監視）

このスタックの強みは、
1. Neon のサーバーレス Postgres が無料枠で 191 時間稼働 + ブランチング可能で、ステージング DB を即作れる
2. FastAPI の自動 OpenAPI から Nuxt 側で型安全クライアントを生成できる（`openapi-typescript`）
3. SSR で SEO に強く、ランディングページとアプリを同一プロジェクトで完結できる

## 市場の現状（2026年4月時点）

- 個人開発者が MVP を出す平均期間は 2〜3 週間（IndieHackers の 2025 年調査）。1 週間を切れる人は上位 10% 未満。
- AI コーディング支援（Cursor / Claude Code）が普及した結果、コード書く時間より「何を作るか決める時間」がボトルネックになっている。
- Neon・Supabase・PlanetScale 等のサーバーレス DB が浸透し、インフラ初期コストが事実上ゼロに。
- 日本語圏では Vue/Nuxt の採用が React より相対的に多く、Nuxt + Python の組み合わせを採る個人開発者が増加中。

## サービスアイデア 1: ContractPing — 契約書自動アラート SaaS

### 概要
中小企業や個人事業主が結んでいる SaaS・サブスク・業務委託契約の更新日・解約期限を一元管理し、最適なタイミングでリマインドする。PDF をアップロードすると AI が更新日・自動更新条項・解約予告期間を抽出し、Slack / メール / LINE に通知。

### 想定ユーザー
- 月 30〜100 個の SaaS を契約している小規模 IT 企業の総務担当
- 業務委託契約を多数結ぶフリーランス・個人事業主
- 副業で複数のクライアントと契約している士業・コンサル

### 収益モデル
- フリー: 5 契約まで
- Pro: 月 1,480 円（50 契約 + Slack 通知）
- Team: 月 4,980 円（無制限 + 複数ユーザー + 監査ログ）

### 技術スタック
- Nuxt 3: ダッシュボード、PDF プレビュー（pdf.js）
- FastAPI: PDF アップロード受付、Claude API で抽出
- Neon: 契約データ + 通知履歴
- Celery + Redis: 日次バッチで通知トリガー
- Resend: メール、Slack Incoming Webhook、LINE Messaging API

### 差別化ポイント
- 既存の契約管理 SaaS（Hubble、ContractS）は法務部向けで月 10 万円〜と高額。**個人〜小チーム向けで 1,480 円という価格帯が空白**。
- LINE 通知に対応する競合がほぼいない（日本固有のニーズ）
- 「自動更新の解約期限○日前」という具体的アクションをワンクリックで完了できる UX

### 1 週間で作れるか
**作れる。** PDF 解析は Claude API に丸投げできる。難所は通知バッチのみだが、Neon の cron 拡張または Render Cron で十分。
- Day 1-2: 認証 + アップロード + DB スキーマ
- Day 3: Claude 抽出パイプライン
- Day 4: ダッシュボード UI
- Day 5: 通知バッチ + Slack/LINE 連携
- Day 6: Stripe Checkout
- Day 7: ランディングページ + デプロイ

## サービスアイデア 2: ChangelogHQ — リリースノート自動生成・配信

### 概要
GitHub のマージ済み PR を取り込み、AI がカテゴリ分類と顧客向けリリースノートを自動生成。生成されたノートを公開ページとして配信し、メール購読・RSS・Slack 配信を一括管理。

### 想定ユーザー
- 個人開発 SaaS 運営者（リリースノート書く時間がない）
- スタートアップのプロダクトマネージャー
- OSS メンテナー（リリース通知を購読者に届けたい）

### 収益モデル
- Free: 月 5 リリース、独自ドメイン不可
- Starter: $9/月（無制限リリース、独自ドメイン、メール配信 1,000 通）
- Pro: $29/月（複数プロジェクト、Slack/Discord 自動投稿、A/B テスト）

### 技術スタック
- Nuxt 3 SSG: 公開リリースノートページ（SEO に強い静的生成）
- FastAPI: GitHub Webhook 受付 + LLM パイプライン
- Neon: ブランチごとに本番/ステージングを瞬時に分岐できる
- Resend: トランザクション + マーケメール
- Stripe: サブスク課金

### 差別化ポイント
- 既存 SaaS（Beamer、Headway、Canny）は月 $49〜と高額か、AI 生成機能が弱い
- **GitHub PR から「顧客視点のリリースノート」へ自動変換**する精度の高さ
- Nuxt SSG により公開ページ自体が高速で SEO に強い（既存競合は SPA で SEO 弱い）

### 1 週間で作れるか
**作れる。** GitHub Webhook → Claude → DB → SSG ビルドという素直な流れ。
- Day 1: GitHub OAuth + Webhook 受信
- Day 2: PR データの正規化と DB
- Day 3: Claude プロンプト調整
- Day 4: 公開ページの SSG（ISR）
- Day 5: メール購読 + 配信
- Day 6: 課金
- Day 7: ドキュメント + ローンチ

## サービイスアイデア 3: MeetingDigest — Zoom/Teams 会議の意思決定だけを抽出

### 概要
会議の録画ファイル（または Zoom/Teams のクラウド録画 URL）をアップロードすると、議事録ではなく「決定事項」「ToDo（担当者・期限つき）」「未解決の質問」の 3 ブロックだけを抽出。Notion・Slack・メールに自動配信。

### 想定ユーザー
- 週 10〜20 件の MTG をこなす中間管理職
- リモートチームのスクラムマスター
- スタートアップ CEO（記憶の外注として使う）

### 収益モデル
- Free: 月 3 会議
- Personal: 月 980 円（会議 30 件まで、Notion 連携）
- Team: 月 4,980 円（共有ワークスペース、Slack 連携、検索可能なアーカイブ）

### 技術スタック
- Nuxt 3: アップロード UI、会議一覧、検索
- FastAPI: ファイル受付 → S3/R2 アップロード → Whisper（OpenAI or 自前）→ Claude
- Neon: 議事メタデータ + 抽出結果（pgvector で類似検索）
- Cloudflare R2: 録画保存
- Stripe + Customer Portal

### 差別化ポイント
- tl;dv、Otter.ai、Notta は「全文要約」を出すが、本サービスは**意思決定と ToDo に絞る**ため使われ方が違う
- Notion の DB に「担当・期限・ステータス」プロパティとして直接書き込めるため、その後のタスク管理にすぐ連動する
- 日本語精度を Whisper large-v3 + Claude で担保（既存 SaaS は英語優先）

### 1 週間で作れるか
**ギリギリ作れる。** 文字起こしのコストが高いので Whisper API（$0.006/分）に依存する設計が必須。自前運用は 1 週間では無理。
- Day 1-2: アップロード + R2 + ジョブキュー
- Day 3: Whisper 連携 + Claude プロンプト
- Day 4: ダッシュボード
- Day 5: Notion / Slack 連携
- Day 6: 課金 + 利用量制限
- Day 7: 仕上げ

注意: 録画ファイルの容量とトランスクリプト処理時間が読みにくいので、初期は「最大 60 分」「同時 1 件」と制約を強くする。

## サービスアイデア 4: PromptPipes — 業務に組み込む LLM プロンプト管理

### 概要
社内で散らばっている「ChatGPT に投げているプロンプト」をカード化して保存・バージョン管理し、変数置換テンプレ・実行履歴・コスト集計まで一気通貫で管理する小規模チーム向けツール。Web UI、CLI、Slack コマンドから同じプロンプトを呼び出せる。

### 想定ユーザー
- 5〜30 人規模の AI ネイティブ企業（コンサル、法務、マーケ）
- 営業文書・採用 JD・カスタマーサクセス返信を AI で量産している中小企業
- 「プロンプトが Notion に散らばって誰が最新か分からない」状態のチーム

### 収益モデル
- Free: 1 ワークスペース、3 ユーザー、20 プロンプト
- Team: 月 $19/ユーザー（無制限プロンプト、Slack 連携、利用量分析）
- Business: 月 $49/ユーザー（SSO、監査ログ、複数 LLM プロバイダ）

### 技術スタック
- Nuxt 3: プロンプトカード UI、Markdown エディタ、diff 表示
- FastAPI: プロンプト実行プロキシ、複数プロバイダルーティング、トークン計測
- Neon: プロンプト + 履歴 + 組織テーブル（Row-level multi-tenant）
- Slack App: スラッシュコマンドで実行
- Stripe: 従量+人数課金

### 差別化ポイント
- LangSmith、Helicone は開発者向けでオブザーバビリティ寄り。**業務担当者がプロンプトを「ナレッジ」として運用する UX に振った**ものは少ない
- 「プロンプト = 業務手順書」という捉え方で、新人オンボーディングや外注管理にも使える
- LLM プロバイダ非依存（Claude / GPT / Gemini を裏で切り替え可能）

### 1 週間で作れるか
**作れる。** プロキシ実装が肝だが FastAPI で 1 日もあれば十分。複雑なのは UI（カード一覧、diff 表示、変数フォームの動的生成）。
- Day 1: 認証 + 組織モデル
- Day 2: プロンプト CRUD + バージョン
- Day 3: 実行プロキシ + コスト計算
- Day 4: 変数フォームの動的生成 UI
- Day 5: Slack コマンド
- Day 6: 課金 + 利用量制限
- Day 7: ランディング

## 個人開発者が1人で作れるかの観点

### 共通する成功条件
1. **AI 推論コストを顧客に転嫁する設計**: 月額に「LLM クレジット」を組み込み、超過分は従量課金にする。さもなくば赤字一直線。
2. **最初の機能を 3 つに絞る**: アップロード・抽出・配信。設定画面や管理画面は後回し。
3. **Neon のブランチング機能を必ず使う**: PR ごとにステージング DB が作れるため、個人開発でもデプロイ事故が激減する。
4. **メールは Resend、決済は Stripe Checkout を使う**: 自前実装は時間泥棒。

### 1人運用で詰まりやすいポイント
- **サポート対応**: 日本語チャットを 24h で返すのは無理。FAQ + 平日返信の SLA を最初から明示する。
- **不正利用**: PromptPipes 系は LLM 無限叩きの不正利用リスク。レート制限と未認証 IP のブロックを Day 1 から入れる。
- **PDF / 録画の重いファイル処理**: ジョブキューを後付けすると地獄。Day 1 から Celery + Redis を入れる前提で設計する。

### 推奨アプローチ
**最も成功確率が高いのはアイデア 1（ContractPing）**。理由:
- 日本市場で価格帯の空白がはっきりしている
- 1 顧客あたりの ARPU が高い（月 1,480 円〜）ため、有料転換 100 件で月 15 万円が見える
- 文章抽出のみで動作するため、コスト構造がシンプル
- 個人事業主層は自分自身がペルソナで、課題検証が高速
- リテンションが高い（解約理由がほぼない）

次点でアイデア 4（PromptPipes）。B2B 単価が取れる一方、競合が増えており差別化の言語化が必要。

## まとめ

このスタック（Nuxt + FastAPI + Neon）は、

- **SSR でランディングと SEO に強い**
- **Python の AI/ML エコシステムをフル活用できる**
- **Postgres ブランチングで本番/ステージングが瞬時**

という 3 つの利点があり、AI 機能を内蔵する SaaS の MVP に向いている。1 週間でローンチした後、最初の有料顧客 10 名を 4 週間以内に獲得することを目標にするのが、個人開発として現実的な KPI だ。

最大の落とし穴は「機能を増やしてしまうこと」。1 週間 MVP の本質は「最小機能で最大の検証」を実行すること。アイデア 1 ならば、最初は PDF アップロード → 更新日抽出 → メール通知の 3 機能だけで十分にローンチできる。Slack 連携も契約一括 CSV インポートも、最初の 10 顧客の声を聞いてから作ればよい。
