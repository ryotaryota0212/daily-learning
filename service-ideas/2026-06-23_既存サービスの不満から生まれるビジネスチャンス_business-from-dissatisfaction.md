# 既存サービスの不満から生まれるビジネスチャンス

**作成日**: 2026-06-23  
**テーマ**: 既存サービスの不満から生まれるビジネスチャンス

---

## 市場概要

- 「不満駆動型スタートアップ」は最も成功確率が高いカテゴリの一つ
- 既存ユーザーが抱える具体的な痛みがそのまま製品要件になる
- PMF（プロダクトマーケットフィット）検証が容易：不満投稿・Redditスレ・レビューサイトが宝庫
- 日本では「我慢する文化」が根強く、声に出ないニーズが多い→逆にチャンス大

**主要な不満収集源**
- Google Playstore/App Store の1〜2星レビュー
- Reddit r/startups, r/entrepreneur の "Why doesn't X exist?" スレ
- Yahoo!知恵袋・はてな匿名ダイアリー
- Twitter(X)の「〇〇使いにくい」投稿

---

## 具体的なサービスアイデア

### 1. SlackFatigue — チャットツール疲れ解消ダッシュボード

**不満の起点**: Slack/Teamsの通知地獄、未読バッジ、チャンネル爆増

**想定ユーザー**
- フルリモートのエンジニア・デザイナー（5〜50人規模チーム）

**サービス概要**
- 全チャンネルの重要度をAIスコアリングし「今日本当に見るべき10件」だけ表示
- ノイズメッセージの自動アーカイブ提案
- 週次「チャット負債レポート」をチームに配信

**収益モデル**
- 個人プラン: $8/月
- チームプラン: $5/人/月（5人〜）

**技術スタック**
- Nuxt (フロント) + FastAPI (バックエンド) + Neon (DB)
- Slack API / Teams Graph API
- OpenAI API（重要度スコアリング）

**差別化ポイント**
- Slackのサードパーティ連携より「ノイズ削減」に特化
- チーム単位での「通知文化改善」レポートで導入効果を可視化

**個人開発で作れるか**: ◎ MVPは1週間。Slack Appの審査が最大ボトルネック。

---

### 2. ReviewFilter — EC/飲食レビューの「信頼できる1件」抽出

**不満の起点**: Amazonレビューのサクラ、食べログの価格操作疑惑、レビューが多すぎて読めない

**想定ユーザー**
- 購買前に口コミを徹底的に調べるリサーチ型消費者（20〜40代）
- 比較検討に時間をかけたくないが失敗もしたくない層

**サービス概要**
- URLを貼るとAIが「信頼度スコア」「感情バイアス」「有益情報密度」を算出
- 「この製品の本当の弱点」を1段落で要約
- ブラウザ拡張でAmazon/食べログ/Googleマップ上にオーバーレイ表示

**収益モデル**
- Freemium: 月10回まで無料
- Pro: ¥480/月（無制限 + 比較機能）
- API提供: EC事業者向け $99/月〜

**技術スタック**
- Chrome Extension (Vue) + FastAPI + Neon
- スクレイピング + Claude API（要約・スコアリング）

**差別化ポイント**
- 既存の「サクラチェッカー」は真偽判定のみ→本サービスは「何が本当の問題か」を抽出
- B2Cだけでなく事業者向けAPIで収益の柱を複線化

**個人開発で作れるか**: ◎ 拡張機能はリジェクトリスクあり。まずWebアプリとして先行公開が堅実。

---

### 3. CalSync — 複数カレンダーの「本当に空いてる時間」可視化

**不満の起点**: Google Calendar + Notion + 会社Outlook + 個人予定が乱立し、日程調整が毎回地獄

**想定ユーザー**
- 副業・フリーランス兼業のビジネスパーソン
- 複数クライアントを抱えるコンサルタント・デザイナー

**サービス概要**
- 複数カレンダーを一元統合し「移動バッファ・集中ブロック・プライベート予定」を考慮した空き枠を自動計算
- Calendlyライクな予約ページ生成（URLをシェアするだけ）
- 「週の理想設計」AIコーチ機能：睡眠・集中・会議の最適比率を提案

**収益モデル**
- 無料: カレンダー2つまで
- Pro: ¥900/月（無制限カレンダー + 予約ページ）
- Team: ¥2,500/月（チーム空き枠の一括管理）

**技術スタック**
- Nuxt + FastAPI + Neon
- Google Calendar API / Microsoft Graph API
- Claude API（週設計レコメンド）

**差別化ポイント**
- Calendlyは「予約受付」がメイン→本サービスは「自分の時間の防衛」がコアバリュー
- 日本の商習慣（移動時間・前後バッファ）に特化した設定

**個人開発で作れるか**: ○ Google/MicrosoftのOAuth審査がやや重い。MVPは3〜4週間。

## 実現可能性の評価

| アイデア | 技術難易度 | 市場規模 | 競合強度 | 個人開発向き度 |
|---------|-----------|---------|---------|--------------|
| SlackFatigue | 中 | 中（BtoB） | 低〜中 | ◎ |
| ReviewFilter | 低〜中 | 大（BtoC） | 中 | ◎ |
| CalSync | 中 | 中 | 中〜高 | ○ |

**優先度のおすすめ**: ReviewFilter → SlackFatigue → CalSync  
ReviewFilterは外部API依存が少なく、ブラウザ拡張なしのWebアプリから始めれば最速でMVP検証できる。

---

## まとめ

- 不満起点のアイデアは「誰が使うか・なぜ使うか」が最初から明確になりやすい
- 個人開発では「既存サービスのAPIに乗っかる」構造が工数を最小化する
- 日本市場は「口に出さない不満」が多い→App Storeレビューや知恵袋の深掘りが差別化のヒントになる
