# マイクロサービス vs モノリスの判断基準と移行戦略

## 概要

「マイクロサービスにすべき」という圧力は常にある。しかし多くの場合、モノリスの方がシンプルで壊れにくい。
AI時代においても「正しい構成を選ぶ判断力」が求められる。スタートアップが最初からマイクロサービスを採用すると、
開発速度の低下・運用コストの爆発・デバッグ難易度の上昇という三重苦に陥る。構成の選択はコードを書く前の最重要決断の一つ。

---

## 仕組みの要点

### モノリスとは
- 全機能を1プロセス・1デプロイ単位として動かすアーキテクチャ
- DBも基本的に1つ（スキーマを分けることは可能）
- 関数呼び出しでモジュール間通信 → レイテンシなし
- 例: FastAPI + Neon の単一リポジトリ構成

### マイクロサービスとは
- 機能ごとに独立したプロセス・デプロイ・DBを持つ
- HTTP/gRPC/メッセージキューでサービス間通信
- 各サービスが独立してスケール・デプロイ可能
- 例: 認証・注文・通知を別々のCloud Runサービスとして動かす

### 判断の核心：「境界の明確さ」と「チーム規模」
- 境界が曖昧 → マイクロサービスにしても分割がズレてリファクタリング地獄
- チームが小さい（10人未満）→ モノリスで十分。分散システムの運用コストが人件費を上回る
- デプロイ頻度・スケール要件が機能ごとに大きく違う → マイクロサービスが有利

---

## アンチパターン vs 正しい設計

| アンチパターン | 正しい設計 |
|---|---|
| 最初からマイクロサービス（分散モノリス）| モノリスから始め、境界が見えてから分割 |
| DBを共有したままサービスだけ分割 | サービスごとに独立したDBを持つ |
| 同期HTTP呼び出しの連鎖（N+1分散） | 非同期メッセージキューで疎結合化 |
| サービス間でドメインモデルを共有 | 各サービスが自分のモデルを持つ（ACL） |
| マイクロサービス = スケールする という誤解 | ボトルネック箇所だけスケールすれば良い |

## 設計例：モジュラーモノリス → 段階的分割

```python
# FastAPIでのモジュラーモノリス構成（推奨出発点）
# app/
#   auth/router.py    ← 認証ドメイン
#   orders/router.py  ← 注文ドメイン
#   notify/router.py  ← 通知ドメイン
#   main.py           ← 全ルーターを束ねる

from fastapi import FastAPI
from app.auth.router import router as auth_router
from app.orders.router import router as orders_router

app = FastAPI()
app.include_router(auth_router, prefix="/auth")
app.include_router(orders_router, prefix="/orders")
# 境界が固まったら orders だけ Cloud Run 別サービスに切り出す
```

分割タイミングの判断基準:
- `orders` サービスだけCPU負荷が高い → スケール要件の乖離 → 分割候補
- `auth` チームと `orders` チームが別れた → デプロイ衝突が増える → 分割候補

## トレードオフ

| 観点 | モノリス | マイクロサービス |
|---|---|---|
| 開発速度（初期） | 速い | 遅い（インフラ・通信の設計が必要）|
| デバッグ | 容易（ローカルで全動作） | 困難（分散トレーシングが必要）|
| スケール柔軟性 | 全体一括 | サービス単位で可能 |
| 障害の分離 | 一部障害が全体に波及しやすい | サービス境界で隔離できる |
| 運用コスト | 低 | 高（サービスディスカバリ・監視・認証が倍増）|
| Cloud Run との相性 | 良い（1サービスにまとめやすい）| 良い（サービスごとにデプロイ）|

## チェックリスト

- [ ] チームが10人以上かつドメイン境界が明確になってからマイクロサービスを検討する
- [ ] まずモジュラーモノリスで設計し、モジュール間の依存を可視化する
- [ ] 分割する場合はDBも必ず分離する（共有DBのままでは分散モノリスになる）
- [ ] サービス間通信は同期HTTP連鎖を避け、非同期（Pub/Sub等）を基本とする
- [ ] Cloud Runの場合、サービス間認証にIAM（サービスアカウント + IDトークン）を使う
