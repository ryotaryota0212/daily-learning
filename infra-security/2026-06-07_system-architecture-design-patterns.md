# システム全体構成の設計パターン（API・DB・キャッシュ・キュー・CDN）

## 概要
「動くコード」より「壊れにくい構成」を設計する力がAI時代に求められる。  
システム全体を俯瞰し、各コンポーネント（API・DB・キャッシュ・キュー・CDN）の役割と接続を正しく設計することで、スケーラビリティ・可用性・コストのバランスが取れる。  
FastAPI + Neon + Cloud Run スタックでも、この構成思考は不可欠。ボトルネックはどこか、どこが落ちたらどうなるかを常に考えながら設計する。

---

## 仕組みの要点

### 基本コンポーネントと役割

| コンポーネント | 役割 | 代表例 |
|---|---|---|
| CDN | 静的資産キャッシュ・エッジでのDDoS防御 | Cloudflare |
| Load Balancer | トラフィック分散・TLS終端 | Cloud Run (自動) |
| Application Server | ビジネスロジック。ステートレスに設計 | Cloud Run (FastAPI) |
| Cache | DB負荷削減。頻繁に読まれる・変化の少ないデータ | Redis / Memorystore |
| Database | 永続化層。スケールが最も難しい | Neon (PostgreSQL) |
| Queue | 非同期処理・ピーク平準化・サービス間疎結合 | Cloud Pub/Sub / Tasks |

### 典型的なリクエストフロー
```
ユーザー
  → CDN（静的コンテンツはここで完結）
  → Cloud Run API（認証・ビジネスロジック）
  → Cache（ヒットしたらDBを叩かない）
  → Neon PostgreSQL（キャッシュミス時のみ）
  → Queue（重い処理は非同期に投げて即レスポンス）
```

---

## アンチパターン vs 正しい設計

| アンチパターン | 正しい設計 |
|---|---|
| 全リクエストがDBを叩く | キャッシュ層でDB負荷を削減 |
| 同期で重い処理を実行 | Queueで非同期化、即座にレスポンスを返す |
| APIがセッション状態を持つ | ステートレス設計 → 水平スケール可能 |
| CDNなしで全トラフィックをAPIに流す | 静的/動的を分離、CDNをエッジに配置 |
| スケールを「後で考える」 | 最初から水平スケールを前提に設計する |

## コード/設計例（Cache-Aside パターン）

```python
# FastAPI + Redis Cache-Aside: DBへの直撃を防ぐ基本パターン
async def get_user(user_id: str):
    cache_key = f"user:{user_id}"

    cached = await redis.get(cache_key)
    if cached:
        return json.loads(cached)          # キャッシュヒット

    user = await db.fetchrow(
        "SELECT * FROM users WHERE id=$1", user_id
    )

    # TTL=300秒でキャッシュに保存（データ鮮度とDB負荷のトレードオフ）
    await redis.setex(cache_key, 300, json.dumps(dict(user)))
    return user
```

---

## トレードオフ

- **キャッシュ導入**: レイテンシ削減 ↔ データの鮮度（Stale問題）・キャッシュ無効化の複雑さ
- **Queue（非同期化）**: ピーク対応・疎結合 ↔ 最終一貫性・デバッグの困難さ
- **CDNキャッシュ**: 高速配信・DDoS軽減 ↔ キャッシュパージのタイムラグ
- **読み取りレプリカ追加**: DB負荷分散 ↔ レプリケーション遅延（Replication Lag）
- **マイクロサービス化**: 独立スケール ↔ 運用複雑性増加。小規模ならモノリスが優位

## チェックリスト
- [ ] APIはステートレス設計か（Cloud Run の複数インスタンスで問題なく動作するか）
- [ ] 読み取り頻度の高いデータにキャッシュ層を設けているか
- [ ] 重い処理（メール送信・画像処理・レポート生成等）はQueueで非同期化しているか
- [ ] DBがボトルネックになった場合の対応策（読み取りレプリカ・キャッシュ・インデックス）を設計段階で考慮しているか
- [ ] 各コンポーネントが落ちたときの挙動（サーキットブレーカー・グレースフルデグラデーション）を定義しているか
