# マイクロサービス vs モノリス：判断基準と移行戦略

## 概要

「マイクロサービスが現代的でモノリスは古い」という誤解が蔓延しているが、これは間違い。
マイクロサービスは**組織の複雑さを解決する手段**であり、技術的なトレンドではない。
誤った選択は開発速度の著しい低下と運用コストの爆発を招く。
AI時代において「どちらが正しいか」ではなく「今どちらが適切か」を判断する力が問われる。

---

## 仕組みの要点

### モノリスの特徴
- 1つのデプロイ単位にすべての機能が含まれる
- プロセス内通信（関数呼び出し）でモジュール間が繋がる
- 単一DBを共有する場合が多い
- デプロイ・テスト・デバッグがシンプル

### マイクロサービスの特徴
- 機能ごとに独立したサービス（独立デプロイ・独立DB）
- ネットワーク通信（HTTP/gRPC）でサービス間が繋がる
- チームごとに独立した技術選定・リリースサイクルが可能
- 運用複雑性（サービス発見、分散トレーシング、障害の連鎖）が増大

---

## アンチパターン vs 正しい設計

| アンチパターン | 正しい判断 |
|---|---|
| 「スタートアップだけどスケールを見越してマイクロサービス」 | チーム5人以下・MVP段階はモノリス一択 |
| DBは共有のままでAPIだけ分割（分散モノリス） | サービス分割 = DB分割がセット |
| 機能単位で細かく分割（nano-service） | ドメイン境界（DDD）で分割 |
| モノリスを一気にマイクロサービスへ移行 | ストラングラーフィグパターンで段階移行 |
| マイクロサービス化してCI/CD・監視未整備 | インフラ基盤が先、サービス分割は後 |

---

## 判断フレームワーク

### モノリスを選ぶ条件（AND条件）
- チーム規模 < 10人、または独立したリリースサイクルが不要
- ドメインがまだ不安定（要件が頻繁に変わる）
- 運用インフラ（監視・CI/CD）が成熟していない

### マイクロサービスを検討する条件
- チームが複数あり、デプロイ競合が問題になっている
- 特定機能のスケール要件が他と大きく異なる（例：画像処理だけGPU必要）
- コンプライアンス上、データを分離しなければならない境界がある

## 移行戦略（ストラングラーフィグパターン）

```
[移行前]
Client → モノリス(全機能)

[移行中]
Client → APIゲートウェイ → モノリス(既存機能)
                        ↘ 新サービス(切り出した機能)

[移行後]
Client → APIゲートウェイ → サービスA
                        → サービスB
                        → サービスC（旧モノリスは廃止）
```

### Cloud Run + FastAPI でのサービス分割例

```python
# モノリス時代: 1つのアプリに全ルート
app = FastAPI()
app.include_router(auth_router)
app.include_router(order_router)
app.include_router(notification_router)

# 分割後: notification だけ別サービスに
# notification-service/main.py
app = FastAPI()

@app.post("/notify")
async def send_notification(payload: NotifyRequest):
    # Cloud Run の別サービスとして独立デプロイ
    ...
```

## トレードオフ

| 観点 | モノリス | マイクロサービス |
|---|---|---|
| 初期開発速度 | 速い | 遅い（インフラ構築コスト大） |
| デバッグのしやすさ | 容易（ローカル1コマンド） | 困難（分散トレーシング必要） |
| 独立スケール | 不可（全体スケール） | 可能（機能単位） |
| 独立デプロイ | 不可（全体デプロイ） | 可能 |
| 障害の影響範囲 | 全機能停止リスク | 局所化できる（設計次第） |
| 運用コスト | 低い | 高い（サービス発見・監視・認証が倍増） |

**結論：モノリスは「悪い設計」ではなく「正しいフェーズの正しい選択」**

## FastAPI + Cloud Run での実践チェックリスト

- [ ] チーム・フェーズに応じて「今はモノリス」と意思決定できているか
- [ ] サービス分割する場合、DB も分割しているか（分散モノリス回避）
- [ ] Cloud Run サービス間の認証に ID トークン（OIDC）を使用しているか
- [ ] 分散トレーシング（Cloud Trace）導入なしにマイクロサービス化していないか
- [ ] ストラングラーフィグで段階移行できる構造（APIゲートウェイ経由）になっているか
